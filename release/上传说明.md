# 发布安装版

## 构建

1. 维护 `VERSION` 与 `CHANGELOG.md`，确认 `程序/channels.json` 的仓库与社区页地址。
2. 构建机器安装 Inno Setup 7，设置 `ISCC` 为 `ISCC.exe` 路径；用户机器不需要编译器。
3. 先保存代码提交，再运行 `node release/prepare.mjs`，自动建立固定提交的独立副本、运行测试、发布审计、构建便携 ZIP 和安装包。产物位于 `dist/candidate-<版本>-<提交>/`。
4. 运行 `node --test 程序/tools/test-publish-files.mjs 程序/tools/test-distribution.mjs`；独立副本回归及安装演练见批次档。
5. 核对安装版与便携版都不含私人配置、密钥、历史或反馈中的个人信息；安装包只装发布清单里的文件（三层文件模型见 `release/README.md`）。

## 上传 GitHub

以候选目录 `release-snapshot.json` 记录的 commit 打标签（不要使用继续开发后的 HEAD），创建 Release，附加以下四个文件：

- `ai-capability-board-v<版本>-windows-x64-setup.exe`
- `ai-capability-board-v<版本>.zip`
- `latest.json`
- `SHA256SUMS.txt`

先上传全部附件再将草稿发布为正式版本。普通用户下载 EXE；自动更新读取最新正式 Release 的 `latest.json`。
首次对外发布必须实测下载链接与清单 SHA256，不能只推代码。
安装包当前未配置开发者代码签名证书，Windows 可能显示未知发布者；不要指导用户关闭系统防护。

## Gitee 与微信群

Gitee 尚未配置；填写真实仓库后再验证发行版下载接口及跳转域名，未验证前不要作为自动更新源启用。
微信群二维码放在 `docs/community.md`，它是固定入口，更新二维码无需重发安装包。

## 数据与回退

安装包不包含私人文件。升级快照保留在安装目录的 `backups/upgrade-*`；配置及历史保持原位。
升级被系统强制中断而无法自动恢复时，在安装目录运行 `runtime\node.exe 程序\tools\\upgrade-lifecycle.mjs rollback`；如运行时已损坏，先保留整个目录再联系维护者。
完整卸载可在 Windows 应用列表执行，默认保留数据；便携用户运行 `runtime\node.exe 程序\tools\\uninstall.mjs` 清理集成后自行保留或删除文件夹。
