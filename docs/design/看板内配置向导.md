## 一、需求层

### 1.1 总体需求

让不懂技术的用户**不经过控制台窗口**完成首次配置：在看板页面里选平台、准备密钥（密钥由 ThinCoder 统一维护，页面不接触密钥值）、
由页面把平台开关合并写进本项目目录的 `config.json`、立刻看到「到底成没成」，并明确「怎么让它自动运行」。密钥值不出本机、不进 URL、不进日志、不落任何页面持久化存储。
（三层需求与逐条用户故事的权威文本在需求档；本节只做设计视角的收敛，不重述。）

### 2.1 方案选型对比

#### 2.1.1 D1 配置写入通道（本批最重要的选型；2026-09-17 起密钥已不在本流程内）

| # | 候选方案 | 判据逐项评估 | 取舍（选定代价） | 结论 |
|---|---|---|---|---|
| 1 | **页内直写**：用户选一次项目文件夹（File System Access API）→ 页面按合并语义写 `config.json`（2026-09-17 起只写它） | 安全：✔ 只写平台开关，不读密钥文件；无 URL / 命令行 / 日志痕迹。目录校验：✔（顶层 `dashboard.html` + 程序侧标志，见 2.2.14）。兼容：Chromium 系。改动面：只加页面模块 | 代价：① 仅 Chromium 系（能力检测 + 兜底面板消解）；② 无 rename，落盘非原子（单次写入 + 失败回滚；控制台向导兜底 2026-09-17 已移除） | **选定** |
| 2 | 协议传参：新增协议动作，把密钥拼进 URL 交给 node 侧写 | 安全：✘ 密钥进进程命令行（任务管理器可见）与 `data/protocol.log`，直接违反 NFR-1 与既有「密钥不进日志」纪律 | 不可接受 | 否决（违反 NFR-1） |
| 3 | 引导用记事本打开 `secrets.json` 手填 | 安全：✔；可用性：✘ 用户诉求正是「不要自己建 JSON」；易写坏 | 仅作兜底保留（既有「编辑密钥文件」按钮） | 否决（不满足 F3 / F4） |
| 4 | 起本地小服务端，页面 POST 给服务端写文件 | 直接撞「不引入服务端 / 监听端口」硬边界 | 不可接受 | 否决 |

#### 2.1.2 D2 首次启用（让自动采集跑起来）的通道

背景事实：注册计划任务必须起进程（`tools/install.mjs`）；而**全新解压的副本上按钮协议尚未注册**（协议由安装流程注册，
见 `tools/register-protocol.mjs:9-19`、`tools/install.mjs:91-95`），此时页面够不着系统侧。因此本选型必须分两态回答。

| # | 候选方案 | 判据逐项评估 | 取舍 | 结论 |
|---|---|---|---|---|
| 1 | **协议一键安装**：向导内按钮 → 新动作 `setupinstall` → 后台隐藏运行 `tools/install.mjs --skip-verify` → 复探测确认真实状态 | 可用性：✔ 零额外操作；安全面：与既有 `collect` / `backup` 同级（固定脚本、无参数）；结果可核对：✔（复探测查计划任务真实存在性） | 仅在「系统侧已启用（协议已注册）」时可用——这是回访用户与「装过没配好」用户的主路径 | **选定（主路径）** |
| 2 | **静默引导脚本**：新文件 `快捷操作\启用自动采集.vbs` 双击 → 隐藏运行同一安装链路（无控制台窗口）→ 等待返回 → 弹中文提示 | 可用性：✔ 无控制台、无 pause；安全面：等于用户自己双击 `安装定时任务.bat`；反馈：中文模态提示（成功 / 失败 + 下一步，经 `tools/setup-notify.mjs`）+ 托盘图标出现 | 多一次双击（浏览器沙箱不允许页面自己注册系统集成）；中文提示机制 = 取退出码 + 通知脚本，退化时内嵌载荷直调 PowerShell（2.2.5）；`.vbs` 全程纯 ASCII | **选定（全新副本的引导路径）** |
| 3 | 沿用 `安装定时任务.bat` 引导 | 带控制台窗口 + `pause`，与「不要弹控制台」的诉求冲突；但它是既有、已验证的路径 | 保留为**失败兜底**文案（例如安装失败要去看详细输出时） | 否决为主路径 |
| 4 | 页面自己实现调度（生成计划任务 XML 让用户导入等） | 仍需用户理解导入流程并双击；与 `install.mjs` 职责重复，两套调度 = 两个真相源 | 不可接受 | 否决 |

**结论（缺漏 2 的答案）**：一次安装动作，两条触发路径——**能点就点（协议一键），点不动就静默双击一次（`启用自动采集.vbs`）**；两条都失败时兜底到
`安装定时任务.bat`（可见控制台，便于看原因）。开启状态一律以「真实计划任务是否存在」为准（A10），不以「用户点过按钮」为准。

### 2.2 架构与接口契约

#### 2.2.1 三条通道总览

| 通道 | 方向 | 载体 | 用途 | 现状 |
|---|---|---|---|---|
| 写通道 | 页面 → 磁盘 | File System Access 目录句柄（用户授权一次） | 只写 `config.json`（平台开关）；密钥文件不读不写；损坏的 `config.json` 可备份重建 | 新增 |
| 动作通道 | 页面 → 系统 | `aiquotaboard://` 协议（隐藏 iframe 触发；既有模式见 `dashboard.html:1745-1751`） | 探测、安装、试采、阈值保存、备份等 | 复用 + 新增 2 个动作 |
| 读通道 | 系统 → 页面 | ① `dashboard-data.js`（既有，页面唯一常规数据源，`dashboard.html:566-583`）；② 目录句柄直读 `data/setup-status.json`（仅向导内使用） | 向导状态与试采结果 | 复用 + 新增状态文件 |

#### 2.2.2 协议动作契约（新增两个；其余动作不动）

| 动作 | 页面触发 | `运行协议.vbs` 分支 | 执行的脚本 | 输出去向 | 结果回读 |
|---|---|---|---|---|---|
| `setupcheck` | 打开向导的「检测」步、点「重新检测」 | 隐藏运行（`sh.Run cmdline, 0, False`） | `tools/setup-check.mjs`（无参数） | 追加 `data/protocol.log` | 页面经句柄读 `data/setup-status.json`（轮询 ≤ 10s） |
| `setupinstall` | 向导「自动采集」步的一键按钮 | 同上 | `tools/install.mjs --skip-verify` | 追加 `data/protocol.log` | 再触发一次 `setupcheck`，以 `autoRun.taskRegistered` 为准 |

纪律（沿用既有）：动作名固定、**不接受任何参数**（无任意命令执行面）；`.vbs` 保持纯 ASCII；命令模板照 `运行协议.vbs:64` 的
`cmd /c <node> "<脚本>" >> "data\protocol.log" 2>&1` 形态；分支写在 `运行协议.vbs:63-97` 的动作分发区。

#### 2.2.3 状态文件契约 `data/setup-status.json`（新增，运行时产物，不进仓库）

| 字段 | 类型 | 含义 | 纪律 |
|---|---|---|---|
| `checkedAtMs` | number | 本次探测时刻 | 页面以此判断「探测已完成」 |
| `platforms` | `{codex,deepseek,glm: boolean}` | `config.platforms` 的生效值（缺省=开启） | 与 `lib/common.mjs:54-64` 的语义一致 |
| `config` | `{parse: 'ok' \| 'broken' \| 'missing'}` | `config.json` 的**可解析性**（不是生效值） | 探测脚本自读原文判定（`loadConfig` 会静默回退默认值，不能据此判断）；只读不修 |
| `codex` | `{found: boolean, note: string}` | 是否探测到 Codex 登录信息 | note 只描述状态，不含凭据 |
| `deepseek` / `glm` | `{found: boolean, source?: string, length?: number, note?: string}` | 是否已有可用密钥、来源标签与长度 | **只报来源与长度，永不报值**（纪律原取自 `tools/setup.mjs`——该文件已于 2026-09-17 移除，现以本节为权威） |
| `secrets` | `{exists: boolean, platforms: string[]}` | `secrets.json` 是否存在、里面有哪些平台键名 | 只有键名，无值 |
| `autoRun` | `{taskRegistered: boolean, taskName: string}` | 计划任务是否真实存在（`schtasks /Query`） | 任务名与 `tools/install.mjs:17` 的常量保持一致 |
| `lastCollect` | `{atMs: number \| null}` | 上次采集时刻（读 `data/state.json`） | 只读 |
| `runtime` | `{nodeVersion: string, portable: boolean}` | 当前运行探测的 node | 便于排查环境 |

#### 2.2.4 新增脚本 `tools/setup-check.mjs` 契约

- 调用：无参数；退出码 0 = 已写盘。
- 职责：确保 `data/` 存在 → 读 config（`loadConfig`）→ **自读 `config.json` 原文试 `JSON.parse`，把可解析性如实写进状态文件**
  （`ok` / `broken` / `missing`；`loadConfig` 会静默回退默认值，不能拿它的结果判断）→ 探测 Codex 登录文件、两家密钥来源（`resolveApiKey`，只取 `source` 与长度）
  → 扫 `secrets.json` 的键名集合 → 查计划任务（名字以 `install.mjs` 的常量为准）→ 读 `state.json` 的 `collectedAtMs`
  → 原子写 `data/setup-status.json` → stdout 一行摘要（进 `protocol.log`）。
- 纪律：不打印、不落盘任何密钥值；错误文本先脱敏（可复用 `tools/first-run-check.mjs:26-32` 的 `maskSecrets`）；
  不修改 `config.json` / `secrets.json` / `state.json`。

#### 2.2.5 新增静默脚本 `启用自动采集.vbs` 契约（纯 ASCII；完成提示 = 中文，含退化顺序）

- 行为：双击 → 定位 node（优先 `runtime\node.exe`，与 `运行采集.vbs:15-16`、`运行协议.vbs:50-51` 同法）→ 确保 `data/` 存在
  → 隐藏运行 `node tools/install.mjs`（输出追加 `data/protocol.log`）→ **等待返回并取退出码**（`sh.Run(cmdline, 0, True)`）
  → 按退出码走**完成提示的退化顺序**（下条）给出成功 / 失败提示（文案要点 + 下一步；正常路径契约见 2.2.13）。
- **完成提示的退化顺序**（2026-09-15 用户「必须中文」裁定无例外；原「通知链路起不来 → ASCII MsgBox」作废）：
  1. **正常**：node 可用且 `tools/setup-notify.mjs` 存在 → 调 `node tools/setup-notify.mjs --ok` / `--fail`（等待返回；成功判据 = 调用未抛错且退出码为 0）→ 由通知脚本弹中文模态提示。
  2. **退化**：上一步未成功（node 不可用 / 通知脚本缺失 / 通知脚本退出码非 0）→ `.vbs` **直调 PowerShell `-EncodedCommand`** 弹**同文案中文框**——两段载荷 `b64Ok` / `b64Fail` 内嵌在本文件里（纯 ASCII）。
     命令行 = `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe -NoProfile -WindowStyle Hidden -EncodedCommand <载荷>`；
     `%SystemRoot%` 经 `sh.ExpandEnvironmentStrings` 展开——该 PowerShell 随 Windows 自带、不依赖 PATH 与 node；`-WindowStyle Hidden` 防控制台闪窗（与 `托盘图标.vbs:19` 同法）。
     该路径可行性已实测（2026-09-15：载荷 416 / 456 字符、零非 ASCII；解码回读与原文一致）。
  3. **理论分支**：第 2 步调用本身也失败（连 PowerShell 都起不来——Windows 实机不存在）→ 才允许 ASCII 兜底 MsgBox（保证不静默）；**标注为「理论分支，实测不可达」**。
- **存在性守卫（可达路径）**：双击位置里找不到 `tools\install.mjs`（如把 `.vbs` 复制到项目外双击）→ 不执行安装，弹**中文**提示
  （第三段载荷 `b64NoInstall` 直调 PowerShell——该时点 `tools\setup-notify.mjs` 同样不在，不经 Tier 1 正常路径；PowerShell 随 Windows 自带、可用）→ 退出码 1。
  该守卫不得用 ASCII 提示（2026-09-16 父侧裁定：可达路径，「提示一律中文」无例外）；若该调用本身也失败（与 Tier 3 同性质的理论分支）→ 允许 ASCII 兜底（保证不静默）。
- **内嵌载荷的实现约束（可维护性硬要求，不是建议）**：三段载荷必须赋给固定名常量 `b64Ok` / `b64Fail` / `b64NoInstall`、各为一条不折行的字符串字面量（T39 据此机判抽取）；
  base64 本身**不可读**——每段**紧邻一行英文注释**（写在载荷行的上一行、单行含两部分）：① 解码后的中文含义（英文描述 + 指向 `tools/setup-notify.mjs` 的同态文案——本文件不得含非 ASCII）；
  ② 再生成命令 `node tools/setup-notify.mjs --emit-b64`（输出可直接粘贴为赋值行）。
- 骨架来源：`托盘图标.vbs:7-19`（`Option Explicit` + 存在性检查 + 工作目录 + 隐藏 Run）；命令构造照 `运行协议.vbs:64`。
- 与 `.bat` 的差异：无控制台窗口、无 `pause`；完成反馈 = 中文模态提示（用户双击后不会错过——对应 NFR-3「每一步都告诉用户现在在干什么」）。
- 纪律：`.vbs` 源码与全部载荷串保持零非 ASCII 字节（GBK 解析风险不回归）；中文只以「`.mjs` 的 UTF-8 文案」与「base64 载荷（正常路径由 `.mjs` 生成、退化路径 `.vbs` 内嵌同源一份）」两种形态存在（A17 机判）。
- 幂等：与 `安装定时任务.bat` 等价，重复执行不产生额外副作用（`install.mjs` 自身幂等）。

#### 2.2.9 安全设计

1. **密钥生命周期（实现约束，2026-09-17 用户裁定改口径）**：向导**不接收、不保存、不显示密钥值**——没有密码输入框，也不读写 `secrets.json`（机判：对密钥文件零读零写）；
   密钥只存在于 `secrets.json` / ThinCoder 配置 / 环境变量（由 ThinCoder 或用户维护）；渲染函数与提示消息只允许使用「来源 / 长度」，永不使用值；
   不得进入 `D`（看板数据对象）、toast 文本、URL、`window.name`、存储 API、console。
2. **目录校验先于一切写入**：校验失败零写入（A3 断言桩上写调用数为 0）；只允许写「所选目录下的两个配置文件名 + `data/` 下的备份副本」。
3. **落盘非原子性（如实登记）**：File System Access 没有 rename/move，无法做「临时文件 + 原子替换」；
   策略 = 一次性写入完整字符串 + 失败时把原内容写回（回滚）+ 向导内「备份并重建」作为最终修复路径（原写「控制台向导」——该向导 2026-09-17 已移除）。测试覆盖回滚分支（T10）。
4. **协议面评估**：新增两个动作均为「固定脚本 + 无参数」，与既有 `collect` / `backup` / `setup` 同级；
   写系统仅限 HKCU（协议注册、计划任务、快捷方式），与本机用户自身权限等价。任何本地页面可经嵌入 iframe 触发这两个动作——
   与既有动作同一暴露面，本批不放大。**登记为已知面**（非本批消解项）。
5. **无网络**：探测与保存全程不联网；试采联网属既有采集行为。
6. **不落敏感日志**：状态文件与 `protocol.log` 只含状态与来源标签；测试夹具不得长得像真密钥（否则会被发布闸门的密文规则拦住）。

7. **写入与采集的并发 / 修复失败残留（如实登记）**：采集任务默认每分钟触发（`tools/install.mjs:24`；默认模板间隔 1 分钟），每次运行都读 `config.json`（`collect.mjs:49`），
   密钥文件在对应平台到点采集时读。页面写入期间内容先落临时缓冲区、`close()` 提交时才替换目标文件（WHATWG File System §2.5：「通常写临时文件」+「预期原子更新」；本机未实测，按最坏情形登记）。
   后果两类：① 瞬态（实现相关，概率低）：提交瞬间恰好撞上一次采集且读到不可解析内容 → 那一次采集用默认值，下一次自愈；
   ② 持续：写入失败且回滚也失败（磁盘满 / 权限 / 占用）时，文件可能被留在失败形态（最坏 = 不可解析）→ 此后每次采集静默回退默认配置
   （`lib/common.mjs:25` 只写一行 stderr，经 `运行采集.vbs:19` 重定向进 `data/collect.log`），**用户无从知晓**。
   对照：`secrets.json` 坏掉相对可见（受影响平台显示「未配置」）；`config.json` 坏掉在本页几乎不可见（默认值与用户配置多数字段一致），故本项专补后者。
   处置：探测脚本如实报告可解析性（2.2.4）→ 状态文件 `config.parse`（2.2.3）→ 向导检测步呈现警告与修复路径（2.2.8）；不做常驻检测——
   未打开向导期间没有提示（残留；打开向导 / 点「重新检测」即刷新，见 2.1.5 D5）。

#### 2.2.13 新增通知脚本 `tools/setup-notify.mjs` 契约（中文提示；新增）

- 调用：`node tools/setup-notify.mjs --ok`（安装六步全部成功）/ `--fail`（退出码非 0）/ `--emit-b64`（打印三段载荷 `b64Ok` / `b64Fail` / `b64NoInstall`——每行一条、形如 `b64Ok = "<base64>"`，可直接粘贴进 `启用自动采集.vbs`；零副作用、不弹框）；参数缺失 / 未知一律按失败报——未知状态不谎报成功。
- 职责：按入参选中文文案（成功要点 = 安装完成 + 回看板点「重新检测」；失败要点 = 有步骤没成功 + 双击 `安装定时任务.bat` 看详细输出）
  → 构造 PowerShell 脚本文本（`System.Windows.Forms.MessageBox` 模态框，标题 = 产品中文名）→ UTF-16LE base64
  → `powershell.exe -NoProfile -EncodedCommand <b64>`（与 `tools/install.mjs:26-29` 的 `ps()` 同法：中文零编码风险、零新依赖）。
- 纪律：中文只存在于本 `.mjs`（UTF-8）与 base64 载荷内（本脚本是唯一文案源——`.vbs` 内嵌载荷由 `--emit-b64` 生成、与本文案同源，见 2.2.5）；命令行载荷（base64 串）零非 ASCII；不透传数字退出码（技术码不进用户文案）。
- 退出码：0 = 弹框链路已执行；非 0 = PowerShell 调用失败（`.vbs` 据此进退化路径——弹自身内嵌载荷；ASCII 兜底仅剩理论分支，见 2.2.5）。
- 可测性（实现约束）：载荷生成 = 可导出的纯函数（如 `buildNotifyPayload(mode)`）；作为模块被 import 时零副作用（不弹框）——弹框只在作为主程序运行时发生；T39 直接断言各段载荷（成功 / 失败 / 守卫，见 3.2 T39）。
- 已知面（如实登记）：弹框由隐藏进程弹出；Windows 前台锁下极端情形可能不置顶（用户已切走浏览器时）——实现可选加 topmost 隐形 owner 窗缓解（不强制），真实可见性 = 人工验收步骤 5 的观察点。

## 三、测试层

### 3.1 自动化边界（为什么有些只能人工）

**实测事实**：`file://` 页面上 `showDirectoryPicker` 存在且可用（`isSecureContext` 为真）；但**原生文件夹选择器无法被自动化驱动**——
CDP 没有对应命令（`Page.handleFileChooser` 只对 `<input type=file>` 生效），因此「真实点击选择器 → 得到句柄 → 真实落盘」这一整段
无法在无头 / CDP 环境跑通。据此把测试分两段：

- **可自动（桩句柄）**：能力检测分支、目录校验与拒绝、平台开关合并写入、坏文件重建、写失败回滚、密钥不外泄（向导对密钥文件零读零写）、错误文案、DOM 无重复 id、
  无 JS 报错、状态文件契约、超时降级 —— 全部用**注入的假目录句柄对象**在无头浏览器里跑。
- **可自动（真机 node 侧）**：`tools/setup-check.mjs` 的状态契约与不外泄、写出的密钥可被 `resolveApiKey` 读出、运行时文件（`data/protocol.log` / `data/state.json` / `data/collect.log` / `dashboard-data.js`）不外泄扫描、规则测试回归、发布闸门。
- **只能人工**：真实选择器交互 + 真实落盘、真实安装（计划任务/托盘；含静默脚本的中文提示弹框）、真实试采、真实浏览器下的句柄持久化（open-1）、Firefox 兜底。

**桩测试机制**（`tools/test-dashboard.mjs`）：把 `dashboard.html` 复制到临时目录（`data/__test-dashboard__/`，gitignore 范围内），
在主脚本前注入一段测试引导脚本——① 安装插桩（存储 API / IndexedDB / iframe src / console 记录调用）；② 装桩
`showDirectoryPicker`（按场景返回不同的假句柄，假句柄实现页面用到的最小面：`getFileHandle` / `getFile` / `createWritable` / 目录枚举）；
③ 注入短超时；④ 驱动真实点击（`#setupStartBtn` 等）；⑤ 把结果写进一个约定的结果节点。用
`--headless=new --virtual-time-budget=<N> --dump-dom` 取回 DOM，解析结果节点后在 node 侧断言并给出退出码。浏览器查找复用
`tools/make-icon.mjs:22-44` 的发现逻辑。**测试不得依赖 IndexedDB**（见 open-1）。

**A13 度量口径（定死，评审轮次 1 修正）**：

- ① 单位 = UTF-8 字节（`fs.statSync().size` 口径）；基线 = 实现开工前对 `dashboard.html` 的实测值（现文 = 2104 行 / 105,976 字符 / 118,045 字节，开工时复核并记录）；上限 = 30 × 1024 = 30,720 字节；测量 = 实现后字节数 − 基线。
- 实现约束（2026-09-15 用户裁定，取代原「超顶即压缩」表述）：**硬顶维持 30,720 字节**；第一原则 = 在满足设计判据的前提下**取增量下限**（优先复用既有函数与样式类、不做投机性抽象——细则见 2.3）。按当前平均密度（≈56 字节/行）折算，+550 ~ +750 行 ≈ +30,000 ~ +41,000 字节：**上限大概率贴边 / 越界**；确实超顶 → **停下报告**（超了多少 / 超在哪 / 能砍什么），不得静默越顶，也不得偷工减料——可能需要用户放宽 NFR-4.1 或另行评估拆分（拆分不在本批）。
- ② 「打开 < 200ms」在虚拟时间下量不到真实墙钟（虚拟时间跳过真实等待）→ 改为非虚拟时间单跑（T31）+「点击后同步可见」约束；`setupWizardOpen()` 的同步渲染为配套实现约束（见 2.2.6）。
- ⑤ 「首屏无影响」的可机判基线 = 与开工前快照同夹具对比（T32）：首屏 id 集合一致 + 加载期插桩计数为 0 + 向导 DOM 懒创建。

### 3.4 人工验收步骤（真实环境，逐条给操作与期望）

1. 在 Edge / Chrome 里打开项目里的 `dashboard.html`（先备份并临时移走 `dashboard-data.js` 以复现「没有数据」）。期望：开屏出现引导，主按钮是「开始配置」。
2. 点「开始配置」。期望：向导打开；先要选文件夹（浏览器弹原生选择框）。
3. 选**错误的**文件夹（如桌面）。期望：明确拒绝，提示不是本项目目录；整个项目目录里没有任何新文件。
4. 重新选择**本项目文件夹**。期望：通过；向导进入「检测」步。
5. 按提示完成「快捷操作\启用自动采集.vbs」双击（全新副本场景；已装用户系统侧已就绪，直接点页面上的「现在就开启」即可，不必进文件夹）→ **先确认弹出中文模态提示（安装结果 + 下一步），点掉它** → 回页点「重新检测」。期望：弹框为中文、内容与安装结果相符（open-2 裁定的核对点）；检测通过，显示本机已有能力；否则「跳过检测」也可继续。
6. 选平台 → 第 4 步看密钥状态（没找到的按提示装一次 ThinCoder 并在里面配好，或点「重新检查」）→ 点保存。期望：出现选择器（若上一步未选）；写入成功提示；**用记事本打开项目里的 `secrets.json`，确认内容与配置前完全一致（向导不写它）**。
7. 打开 `config.json`，确认 `platforms` 与所选一致，其它字段未被改动。
8. 点「现在拉一次」。期望：≤ 90 秒内出现每个平台的结果行（成功显示余额/用量；未配置/失败显示人话原因与下一步）。
9. 关闭浏览器、重新打开看板并再开向导。期望：句柄若能持久则不再要求重选（open-1 核对点）；不能则重选一次，功能不受影响。
10. 用 Firefox（或屏蔽 `showDirectoryPicker` 的浏览器）打开看板并开向导。期望：直接给兜底面板，两条替代路径可用，无 JS 报错。

13. **过时指引缺席核对**：向导主路径（开屏 → 步骤 0–7）逐屏不出现「必须双击 .bat 才能配置」类过时指引；再搜 `dashboard.html` 的「安装定时任务.bat」「.bat」命中点，确认全落在兜底语境（失败兜底文案 / 带 `data-fallback` 的链接）。期望：核对通过（步骤 6 的兜底引导不在排除面内）。**2026-09-17 追加：凡让用户双击脚本处，路径必须写全「打开看板文件夹 → 进『快捷操作』→ 双击『X』」；裸文件名或旧顶层路径（如「双击项目里的 X」）判不合格。控制台向导已移除，`首次配置.bat` 不再存在。**
