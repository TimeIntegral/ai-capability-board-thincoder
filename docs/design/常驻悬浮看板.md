## 一、需求层

### 1.1 总体需求

把看板已有的本地数据再给一个**不占地方、不打断手的看法**：一条贴屏幕边的中型胶囊（悬停展开）与一张微型小卡片（一直看得见），围绕 ThinCoder 的实时状态与项目轮次组织内容，读的是与看板同一份数据文件。它必须常驻而不碍事（收起态点击穿透、不抢焦点、透明），必须开销接近零，必须能被正常安装、升级、卸载，且不引入任何第三方依赖。

三层需求（US / NFR）的权威文本在需求档；本节只做设计视角收敛，不重述。

### 1.4 本批不做（边界）

- 不做多屏、不做跨屏拖动（只支持主屏；`spike:16`）——用户已认可为已知边界。
- 贴上/下边时**内容不转 90°**（几何正确、内容不转，`lib §4.9` 头部注释）。
- 拖动起点只在展开态成立（收起条是穿透热区，`spike:8`）。
- 面板不做自己的设置界面、不接收输入（不做开关、不做配置；口径随 `config.json` 与看板）。
- 不改采集器 / 规则引擎 / 数据层存储格式；不新增服务端、监听端口、第三方依赖。
- 不做字节级可复现构建（exe 天生不可复现，`probe:76`）。
- `CHANGELOG.md` 由主 agent 落笔；`README.md` 同步由主 agent 收口时落。

## 二、设计层

### 2.1 方案选型对比

#### 2.1.1 D1 技术栈：编译版 C# 5 + WPF exe（已拍板）

| 项 | 实测值（出处） |
|---|---|
| 编译器 | 系统自带的 .NET Framework 4 编译器（`%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`；`probe:32`） |
| 需要的工具 | 无 MSBuild、无 NuGet、无 dotnet、无联网；参考程序集直接指到运行时目录（WPF 三件 + `System.Xaml` / `System` / `System.Core` / `System.Xml`，`probe:33`） |
| 编译耗时 | 158–185 ms（同源五次，`probe:35`） |
| 语法上限 | **C# 5**：C#6（`$"…"` / 自动属性初始化 / 表达式体成员 / `nameof`）与 C#7（`out var` / `is T t` / 元组）均编译失败（`probe:45-50`） |
| 窗口属性 | 逐像素透明（跨边缘相邻像素 `diff=0`）、点击穿透、置顶、不抢焦点、不占任务栏（OS 层读回，`probe:59-65`） |

**为什么选它**：常驻工具的两个硬指标——启动与内存。实测编译版窗口可见 0.351s、工作集 122MB；PowerShell 版 1.707s、326–344MB（`probe:142`、`probe:150-154`）。
**否决的备选**：留在 PowerShell + WPF——空转只差 1.5 个点左右（`probe:209`），但启动与内存差距是产品级的（`probe:207-210`）；Electron / 内嵌浏览器类方案未实测，按「零第三方依赖」硬约束直接否决（不引入任何第三方运行时）。

#### 2.1.2 D2 编译与产物来源（已拍板：必须在冻结提交上编译）

- 编译**只发生在 `release/prepare.mjs` 建出的冻结工作树里**（`prepare.mjs`：`git status` 干净 → `git rev-parse HEAD` → `git worktree add --detach`，之后全部构建都在该工作区跑，`probe:173-175`）。
- exe 与构建记录**都不进 git**：路径落在 `.gitignore` 覆盖的 `程序/bin/` 下。
- 来源保底 = **记录 {提交, 源文件清单及其 SHA256, 编译器, 出厂 SHA256}**，发布闸门按它核对（范例：`publish.mjs:447-469` 的 `inspectRuntime()`）。
- **不做**「重编一次哈希要相等」的验收：exe 不是字节可复现（两次编译 16,384 字节里有 17 字节不同：PE `TimeDateStamp` 与模块 MVID；`probe:76`）。探针另提供语义等价判定（方法 IL 逐字节比，23/23 个方法相同）作为可选佐证（`probe:77-82`）。

#### 2.1.3 D3 第一刀：呼吸动画（已拍板；与栈无关）

- 实测：连续呼吸动画 15–18%/核（三个候选全一样：基线 17.94、C# 轮询版 16.66、编译版 15.17；`probe:95-97`）；降到 2fps → 0–2%/核（编译版 0、PowerShell 版 0–2.3，`probe:118-119`）；完全去掉 → 编译版 0%、PowerShell 版 1.5%（`probe:115-116`）。
- 机制：窗口是分层窗口，每画一帧 = 整窗重绘 + `UpdateLayeredWindow`（≈0.25%/帧，`probe:123-125`）。
- **本设计默认：直接去掉**（那条呼吸只动一根 8px、5% 白发丝描边的透明度，`spike:69`、`probe:203`）；若要保留，用计时器手动跳帧到 2–4 fps（`probe:204`）。档位取舍见 2.6 open-1。

#### 2.1.4 D4 数据来源：看板数据文件是唯一真相源

面板**不复用采集器、不直连平台、不读采集内部状态文件**：只读 `dashboard-data.js`（看板读的同一份）与 ThinCoder 自己的会话/进程文件（`%USERPROFILE%\.thincoder`，`lib §4.2/4.4`）。
**否决的备选**：面板直连平台接口（多一处凭证使用面、多一个口径分叉）；读 `data/state.json`（把面板钉死在采集内部结构上，且时间戳语义与看板展示层不一致）。

#### 2.1.5 D5 位置记忆：用户数据目录

写 `%LOCALAPPDATA%` 下的面板状态文件（原型：`%LOCALAPPDATA%\AICapabilityBoard-spike\window-state.json`，`spike:14`；落位口径见 `lib §4.10`、`spike:16`）。
**否决**：写仓库（把本机状态丢进别人的工作树）、写安装目录（升级/卸载会动它，且与「用户数据不写安装目录」的既有口径冲突）、写注册表（无先例、排查困难）。

#### 2.2.2 数据读取契约

| 数据 | 来源 | 读法 | 读不到时 |
|---|---|---|---|
| Codex 额度 | `dashboard-data.js` → `window.DASHBOARD_DATA` | `codex.atMs`、`codex.fiveHour.usedPercent/resetAt`、`codex.weekly.usedPercent/resetAt` | 该块读数写 `—`，不画弧（不假装 0） |
| 余额 | 同上 | `deepseek.totalBalance/atMs/carried`、`glm.balance/atMs/carried`、文件级 `generatedAtMs`、`cards.<平台>.show`。**与额度同一条路**：现场读（`Model.Build`）里真读一遍；采集中原地重写文件时会重读重解（3 次 / 150ms） | 读到过 → 保留上一份好数据（按 2.2.7 的陈旧规则变暗，不假装 0、也不清空）；从没读到过 → 该家写 `—` 且一个圈都不画（`spike:67`） |
| 今天·这个项目 | `%USERPROFILE%\.thincoder\sessions` 下的槽位文件 | 槽位 `updatedAt` / `turnCount` / `cwd`（项目名取目录名） | 空态（见 2.6 open-7） |
| 近 7 天 | `data/attribution.json` → `thinCoder.projects[]`（按 `cwd` 匹配） | `turns7` / `sessions7` | 无该行时用同一套会话文件现算，并标注「现算」（`spike:48`、`spike:63`） |
| 当前进展 | `%USERPROFILE%\.thincoder\logs\agent-<本地日期>.log`（今天，没有就读昨天）+ `%USERPROFILE%\.thincoder\peers\*.json` | 最后一条**轮次内** JSONL 事件的 `ts` 与事件名（非轮次的后台事件不算，名单与理由见 2.2.6）：`turn:end` = 一轮收尾；其余（`tool:call` 等）= 正在干活。**三态：正在干活 / 等你回答 / 空闲**，判据三条缺一不可 —— 进程活着、最后一条轮次内事件不是 `turn:end`、没过 30 分钟；进程来自 `peers/*.json` 的 `pid` 是否还在（5 秒探一次）。历史遗留的四态里「20 秒内有写入 = 正在运行」把「停在那儿等你」也算成在跑，已废。**日志读不到**：词条只按活进程判，计时与轮次那一整行不显示（不写 0、不写「—」） | `PROGRESS_STALE_MIN=30` 分钟封顶：最后一条轮次内事件超过 30 分钟就不再冒充正在干活 |
| 本会话轮次 | `%USERPROFILE%\.thincoder\sessions` 槽位文件（`.manifest` 里的 `turnCount`） | 取最新槽位的 `turnCount`（真数据实测 151 / 152 轮） | 不显示轮次 |
| 本会话模型累计 | 同上两份 agent 日志（今天 + 昨天，跨零点回看） | 每条 `llm:done` 的 `ms` 累加（缺 `ms` 用起止时刻兜底）+ 还没收到 `done` 的 `llm:start` 至今；同一条 stream（`child` id，主 agent 为空）内后进先出配对；在飞超过 `MODEL_OPEN_CAP_MS=30` 分钟当残留不计。**只算本会话**：起点 = 最新槽位 `sessionId` 里的铸造时刻（`<pid>-<epochMs>-<rand>`，真机 49 份 manifest 同一形状；解不出退回「今天 + 昨天」整天）；子代理的 `llm:*` 也算 | 一条 `llm:*` 都没有 → 这个数推不出来 → 计时不上屏（不写 0、不写「—」） |
| 子代理 | 同上 agent 日志 | `child:*` 事件：同 id 出现任意非 `spawn/start` 的事件即收工；在跑 → 「子代理 N 个在跑 · 最长 X」 | 0 个 / 推不出来 → 这一行空串、不上屏 |
| 余额节奏 | `<安装根>/data/history/<平台>.jsonl`（采集器每次采集追加一行；当前默认 `balanceMinutes = 1`，即每分钟一行） | 只累计下降（消耗），升 ¥1 以上 = 充值：**充值不算消耗、充值后重新起算、跨充值不累计**；以最后一次充值为窗口起点，`k = floor(累计消耗 / ¥10)` ≥ 1 时取最近一块 → 「最近 ¥10 用了 X」；不足 ¥10 → 「充值后花了 ¥X · 用时 Y」；近 24 小时没花钱 → 「最近 24 小时没花钱」 | 没历史文件 → 这一行不显示；**任何情况下不出现 Infinity / NaN** |
| 今日已消耗 | 同上（同一个 `Cadence` 解析器，不重读一遍文件） | **与网页看板框选统计的「净消耗」同一把尺子**：只看 **本地 0 点之后**的采样点，相邻两点之间**只累计下降段**；上涨 = 充值，不是花钱 —— 不计入、也不冲抵（所以「首−末 + 期间上涨」与「下降段合计」是同一个数）。0 点那一刀按采样点切：跨 0 点那一段（前一个采样点在昨天）不算今天；这家是哪家就跟余额同一家（不合并成一个总数） | 历史读不到 / 今天没有采样点 / 今天只有 1 个采样点（算不出差值）→ **整组不显示**（不显示 0、不显示「—」）；理由记在布局树读数 `cardTodayWhy` |

读取纪律：一律**只读**（唯一写面是面板自己的状态文件）；解析失败按「读不到」处理；不读 `secrets.json`、不读 Codex 的 `auth.json`（面板没有凭证需求）。
刷新节奏照原型：100ms 光标轮询 / 1s 当前进展走秒（词条 + 已 X + 轮次）/ 5s 状态重读 / 30s 数据重读（`probe:131` 记录编译版候选 A 的四个计时器即此四项）；其中两项周期性重读合计只值 ≈0.1 个点（`probe:117`）。读写编码一律 UTF-8。
JSON 解析用 .NET Framework 自带程序集（本机目录里 `System.Web.Extensions.dll` 与 `System.Runtime.Serialization.Json.dll` 均在；**引用哪一条、C# 5 下编译是否通过未实测** → 2.6 open-6，实现第一步用最小样例验证）。

#### 2.2.3 形态与几何契约（照抄原型实测值）

| 项 | 值 | 出处 |
|---|---|---|
| 收起条 | 垂直于屏幕边那一维 = **8 DIP**；长边 = 展开面板沿边那一维（同一个数，代码里没有第二个长度常量）；内凹圆角 6 DIP | `spike:10`、`lib:1069` |
| 展开面板 | 宽 232 DIP（`$PANEL_W`）、内凹圆角 14 DIP；高 = 内容算出（**328 / 410 / 466 DIP**，对应余额段 0 / 1 / 2 家） | `spike:10`、`lib:1070` |
| 悬停热区 | 34 DIP 深（比看得见的宽 4 倍） | `spike:6`、`lib:1075` |

#### 2.2.7 陈旧判据契约

- **按数据源各算各的**，不拿一个阈值一刀切（`lib §4.12`）：
  - 额度：`codex.atMs` 距今 > **45 分钟** → 陈旧（45 分钟 = 5h 窗口的 15%）；
  - 余额：**每家自己的 `atMs`** 距今 > **10 分钟** → 该家陈旧（约 10 个采集周期没刷新 = 采集停了或这家一直读不到；采集周期当前为 1 分钟）；该家没有时间戳时退回文件级 `generatedAtMs`；
  - **时间戳缺失 → 不判旧**（不假装旧、也不假装新）。
- **只让读数的数字与圈变暗**（透明度 0.45）；状态点 / 进展词 / 计时与轮次 / 子代理行 / 余额节奏行 / 写入龄期**一律不碰**（`spike:14`、`lib:3246-3249`）。
- 陈旧与否**渲染时现算**（数据不变、时间在走，陈旧自己会变），不把结论冻进模型（`lib §4.12` 头注）。

## 三、测试层

### 3.1 自动化边界（为什么有些只能人工）

- **可自动（不需要窗口）**：编译与来源核对、发布链三层分类与断言、口径与几何的**自检模式**（面板 exe 提供 `--selftest`：用假数据夹具跑一遍口径/几何/陈旧/扫动参数并打印读数行——照原型 `-SelfTest` 的做法，`spike:27`）、位置记忆坏文件夹具、单实例、`.vbs` ASCII、文案词表、既有回归。
- **可自动但依赖真实桌面**：窗口属性读回（逐像素透明 / 穿透 / 置顶 / 不抢焦点 / 不占任务栏）——做法照 `probe` 的探针（启动进程 → OS 层读回扩展样式 + 跨边缘像素比对 + `WindowFromPoint`，`probe:53-65`）。无桌面会话时跑不了，登记为**半自动**（真机 + 脚本）。
- **只能人工**：悬停展开与移开的体感、拖动与四边着陆的手感、微型卡片拖动、位置记忆跨重启、运行时开销采样、真机升级/卸载演练、SmartScreen 首次运行体验、动画降频观感（open-1）。
- **不进快速门禁**：自检与真机读回都远超既有快速门禁的时长量级 → 按「开发期工具」登记（3.5）。

### 3.4 人工验收步骤（真实环境，逐条给操作与期望）

1. 装好一份独立安装版（不是开发目录），确认桌面/「快捷操作」里有面板入口。
2. 双击「悬浮看板」：屏幕右缘竖直正中出现收起条（8 DIP 宽、与展开同高），不抢焦点、任务栏不多按钮；鼠标靠近 → 展开成面板（额度两环 + 余额段 + 今天·这个项目 + 状态）。
3. 打开任务管理器观察 5 分钟（鼠标停留在远离热区处）：面板进程单核中位应 ≤3%（对照：改动画前是 15–18%）；随后用探针脚本复测一次并留读数。
4. 拖动：把展开的面板往外拖 ≥36 DIP 松手 → 变成微型卡片且落在鼠标处；把卡片拖到左/上/下/右四条边附近松手 → 变回胶囊并贴最近那条边、沿边落点 = 松手位置；未达阈值松手 → 回贴边；微型未着陆 → 反馈退回。
5. 关掉面板再打开 → 回到上次的形态与位置；把屏幕分辨率调小一档再打开 → 位置被夹回可见区（不丢偏好、不弹窗）；把状态文件改坏再打开 → 回默认位置、不弹窗不报错。
6. 微型卡片：确认当前进展词（正在干活 / 等你回答 / 空闲）、「模型 H:MM」与「N 轮」都在场；这一行的「模型」数是**本会话模型累计运行**（大模型真正在跑的时间，不是进程年龄、也不是上一步等了多久）：连续发几轮后它会涨，你停下回话时它不涨；在 ThinCoder 里发一句话 → 词条、写入龄期跟着变（**状态永远实时**）；等一轮跑完停在那儿 → 词条从「正在干活」变「等你回答」。大环确认写的是「Codex 5h」下方的剩余 %（不是 7 天，也不是「两个窗口里更紧的那个」）。**卡片底部两组：上排两个小灰标签「余额」「今日已消耗」，下排两个数字（左「DeepSeek ¥…」或「智谱 GLM ¥…」、右今日金额）**，没有小圆环、没有「1 圈 = ¥X」；项目名行、「模型 H:MM」行、两组两行，四行分开不叠字。**今日已消耗对着网页看板核一次**：在看板里框选今天 0 点到现在，看「净消耗」——应等于卡片右下那个数（充值不算）；今天没花钱就显示「¥0.00」；刚过 0 点、今天还没有采样点（或今天只有 1 个采样点）→ 这一组整组不显示（不是 0、也不是「—」）。展开态：确认余额段每家下方那行「最近 ¥10 用了 X」与子代理行都清楚可读（节奏行 10.5 DIP、子代理行 9 DIP），右侧子代理行不压到状态词，展开面板三档高度（328/410/466）与改动前一致。
7. 升级演练：面板运行中直接跑一次覆盖安装 → 安装过程不应因文件锁失败；装完面板在跑（或由安装器收尾拉起）。
8. 卸载演练（卸载器对话框选「保留数据并卸载」与「连同数据一起删除」各一次）：面板进程被停掉；选删除时面板状态文件按清单处理、`%LOCALAPPDATA%` 下（或安装目录内）不留孤儿。
9. 双击入口再点一次（面板已在运行）：唤出已有窗口，不出现第二个浮窗。
10. 陈旧核对：临时移走/改名 `dashboard-data.js`（或用旧副本）→ 额度与余额读数变暗、状态块照常；恢复文件后读数回到正常亮度。
11. 文案核对：逐屏看面板（收起 / 展开 / 微型 / 空数据）→ 除数字与固定标签外无多余文字，无解释性句子。
12. 减少动态效果：系统「辅助功能 → 视觉效果 → 动画效果」关掉后重开面板 → 展开/收回、变形、扫动全部瞬时，功能不差。
13. SmartScreen / 杀软：在干净用户机上首次运行 exe，记录实际提示与处理方式（如实登记，不假装通过）。
14. 多屏边界核对：接一块副屏，把面板拖到副屏附近 → 位置被夹回主屏（本批已知边界，如实记录现象）。
