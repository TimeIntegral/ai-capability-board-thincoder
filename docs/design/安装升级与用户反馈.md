# 设计文档：安装升级与用户反馈

## 1. 安装与存储

采用 Inno Setup 编译中文、当前用户安装包。仅构建机器需要编译器；用户使用内置 Node。
默认装入用户本地应用目录，保留现有根目录 config/secrets/data 存储契约，避免破坏网页文件夹授权。
程序通过发布白名单部署，私人文件永不打包或覆盖。安装版及便携版均可原位升级。
这是对早期建议“程序数据分开”的调整：首批优先兼容现有无服务端架构，数据分目录迁移不在本批。

## 2. 更新与反馈

- `程序/channels.json` 保存公开仓库及固定社区页；空地址表示尚未配置。（2026-09-17 从 `release/` 移入程序目录：`release/` 是构建机专用目录，不再随包发给用户；构建器与安装版运行时读的是同一份文件）
- `lib/updates.mjs` 负责版本比较、HTTPS/来源白名单、响应大小限制、下载及 SHA256 校验。
- `tools/update.mjs` 在独立锁内检查公开 latest.json，状态写入 data/update-status.json 和独立浏览器注入文件。
- 页面加载独立 assets/support.js，通过固定协议动作检查/下载/设置，不从协议接收任意下载 URL。
- 检查失败保留已验证版本与提示；自动检查日限频，手动检查限短期重复；设置持久化。
- 新版本下载到本机缓存；点击更新才启动安装器，安装器复核路径、备份并停止所属任务后原位升级。
- 程序升级前快照使用明确清单，目录操作限制在安装根；失败恢复快照，成功保留备份。数据不做破坏性迁移。
- 社区页是公开 Markdown 固定路径；二维码由维护者更新。页面没有二维码时明确告知未开放，保留仓库 Issue 反馈。

## 3. 验证设计

独立临时副本运行已有规则和看板测试；新增真实文件测试验证版本比较、恶意地址、哈希错误、下载失败、状态设置、快照恢复、敏感数据保留及安装包清单。
独立浏览器测试验证更新/反馈可见性和 DOM 注入安全。编译实际 EXE，使用隔离模式测试安装/覆盖升级/卸载，隔离模式不注册系统任务与协议。
隔离模式不代表真实系统集成验收；未经真机执行的项目单独记录。

## 4. 发布依赖

GitHub 已从本地 remote 确认。Gitee 地址及微信群入口等待用户提供。
正式 latest.json 在安装包校验和生成后产出；只允许来源白名单内的 HTTPS 下载。仓库公开/上传动作须有可用账户能力与目标地址。
