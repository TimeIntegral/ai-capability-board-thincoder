## 一、总体目标

给已经装了看板的用户解决「看板要打开网页才看得见」：把**同一份本地数据**搬到屏幕边上——**不打开网页、不抢焦点、不挡鼠标**，抬眼就能看到「Codex 还剩多少、余额还剩多少、ThinCoder 现在在不在干活」。

三档信息层级（同一份本地数据的三种看法，能力互补、互不替代）：

| 档 | 形态 | 什么时候看 | 谁提供 |
|---|---|---|---|
| 大型 | 网页看板 `dashboard.html` | 坐下来细看 | 已有：趋势历史、热力图、额度去向、提醒流水 |
| 中型 | 贴屏幕边缘的胶囊（本批新增） | 鼠标往边上一靠就看一眼 | 本批：Codex 5h / 7 天剩余、余额圈、今天·这个项目、状态 |
| 微型 | 桌面上的小卡片（本批新增） | 一直看得见 | 本批：状态、项目名、本会话模型累计运行时长、Codex 5h 额度环、余额一行（家名 + 金额） |

**定位依据（用户原话，2026-09-27）：「一定要紧密结合 ThinCoder 的功能。这才是我们的灵魂。」**
中型与微型两档不是「额度挂件」——它们围绕 ThinCoder 的实时状态（正在运行 / 等你回答 / 已完成 / 今天没用过）与项目轮次组织，读的是 ThinCoder 自己的会话与进程心跳。

**一句话验收**：装好之后，用户**不打开网页**也能在屏幕边缘看到 Codex 额度、余额与 ThinCoder 当前状态；鼠标移开不挡任何操作；关掉再打开还在原处；常驻开销接近零。

范围：

- 只读本机数据（沿用看板既有数据口径，**不新增数据源、不改采集链路**）；不联网。
- 只支持**主屏**（多屏是后续批次，本批明确不做）。
- 实现栈已拍板：**编译版 C# exe + WPF**（系统自带编译器，语法上限 C# 5）——需求层只约束「零第三方依赖、长期常驻不烧 CPU、不抢焦点、形状外就是桌面」，技术细节见设计档 2.1。

## 二、功能用户故事

### US-1 不打开网页也能看到额度与余额

**作为一个正在用 ThinCoder 写活的用户，我想要屏幕边上常驻一条极窄的胶囊，鼠标靠近就展开成完整面板，以便不打断手上的事就能看到 Codex 5 小时 / 7 天还剩多少、两家余额还剩多少。**

范围边界：面板只显示不接收输入（不做配置、不做操作入口）；面板内容口径与看板完全一致（见 US-6）。

### US-2 它不该挡我做事

**作为一个用鼠标干活的人，我想要收起态**完全点不到**（鼠标直接穿过它点到下面的窗口）、不抢焦点、也不在任务栏多一个按钮，鼠标一靠近就展开、一移开就立刻收回，以便它常驻但不碍事。**

范围边界：悬停展开、移开立即收（150ms 防抖）；收起条的高度与展开面板**沿屏幕边那一维同高**（收起/展开之间不跳高，用户明确要求）；展开态不穿透（要能拖动、要能读）。

### US-3 想把它放到别处

**作为一个喜欢自己安排屏幕的人，我想要把展开的面板往外一拖就变成微型小卡片、把小卡片拖到任意屏幕边附近松手就变回贴边胶囊，贴哪条边都行（上下左右），落点就是我松手的位置，以便按当下在做的事安排它。**

范围边界：拖动只能从**展开态**开始（收起条是穿透热区，点不到）；转换阈值与落点规则照原型实测值（设计档 2.2.3）；贴上/下边时**内容不旋转**（本批允许的简化，见边界）。

### US-4 关掉再打开还在原处

**作为一个把面板摆好的人，我想要关掉它再打开、或者下次开机时，它回到我上次放的位置和形态，以便不用每次重新摆。**

范围边界：屏幕变小 / 换屏导致存下的位置跑出可见区时**夹回可见区**（能修就修，不许静默丢弃偏好）；只有文件缺失或损坏才回默认位置，而且**不报错、不弹窗**；只记主屏坐标（多屏边界见范围）。

### US-5 微型卡片：一直看得见的那一眼

**作为一个想随时扫一眼状态的人，我想要一张浮在桌面上的小卡片（228 × 100），上面是「状态 + 项目名 + 本会话模型累计运行时长 + Codex 5h 的额度环 + 「Codex 5h」下面一行「下次重置 HH:MM」+ 底部两组「标签 + 数字」（余额 / 今日已消耗）」，以便不用展开任何东西就知道现在在不在干活、这一会话里模型到底跑了多久、五小时额度还剩多少、下次什么时候重置、今天已经花了多少钱。**

范围边界：卡片**不穿透**（要能拖着走）、**尺寸固定（228 × 100），不因家数或内容多寡再变**；余额只放**最紧的那一家**（读得到的那家里余额最少的），只写家名与金额，不画圈；底部两组卡宽不变的前提下并排：上排两个小灰标签（「余额」/「今日已消耗」）、下排两个数字（左「家名 + 金额」、右今日金额，同号字）；**真装不下就这一组整组不显示**（不叠字、不截断、不悄悄缩字号）。用户口径（2026-11-03）：**「Codex 5h」下面加一行「下次重置 HH:MM」**（5h 额度的重置时刻；`resetAt` 读不到、或那个时刻已经过去，就**这一行整行不显示** —— 不写占位符、不猜、不写「—」）。这一行要 11.64 DIP，而原来那处只剩 4.46 DIP：**用户选方案 ① —— 卡片高 90 → 100 DIP（宽 228 不变）**，长高的 10 DIP 挪给底部两组，新行落在「Codex 5h」与「余额」之间；版面见设计档 2.2.6。

### US-6 看到的是同一份真相

**作为一个核对数字的人，我想要面板与看板的数字与口径完全一致——Codex 显示「还剩多少」（剩余 = 100 − 已用，先减后取整）、余额按每 ¥100 一圈画、今天只算本地 0 点起的轮次、今日已消耗 = 本地 0 点起的下降段合计（充值不计）、看板里关掉的平台整组不出现，以便两边对得上、不被两套口径搞晕。**

范围边界：面板不自己发明口径，也不自己请求平台接口；两家平台共用一个余额单位（可比优先，不许各家自选）；读不到就写 `—` 且不画圈，**绝不假装 0**；今日已消耗算不出来（今天没采样点 / 只有 1 个采样点 / 历史读不到）就**整组不显示**（不显示 0、不显示「—」）。

### US-7 读数可能是旧的，但状态永远实时

**作为一个在意「它现在到底在不在干活」的人，我想要数据陈旧时只有读数变暗（额度与余额各自按自己的时间戳判陈旧：45 分钟 / 10 分钟），状态点、状态词与模型累计时长永远是实时的，以便一眼分清「数据旧」与「没在干活」。**

范围边界：不出现「数据过期」弹窗或提示条；时间戳缺失时不判旧也不判新（照实按无时间戳处理）。

### US-8 数字变化要看得懂

**作为一个盯着数字变化的人，我想要读数变化时弧长与数字一起用 240ms 平滑扫到新值（不是跳变）、首次渲染不扫，且系统开着「减少动态效果」时全部走瞬时，以便变化看得清、也不冒犯对动效敏感的人。**

范围边界：变化小于显示分辨率时不扫；换单位（换尺子）时直接落位不扫。

### US-9 装了就有，升级不打架

**作为一个不想管安装细节的人，我想要装完就能在屏幕边上看到它、桌面上/「快捷操作」里有一个能再次唤出它的入口，升级时它能被正确停下再换文件、卸载时能被清理干净，以便它像个正常软件而不是需要手工照顾的脚本。**

范围边界：升级链不得按进程名裸杀（只认本安装目录下的那个 exe 路径）；卸载默认保留用户数据（位置记忆按数据口径处理）；不在开发目录注册任何系统集成。

### US-10 提示信息一律中文、字数极少

**作为一个只想扫一眼的人，我想要面板上除了必要数字与固定标签之外没有多余的字，也没有任何解释性句子，以便一眼看完而不是读一段话。**

范围边界：用户可见文案一律中文；能少写字就少写字（用户铁律）；单位换算等必要说明只在真的发生换算时出现。

## 三、非功能标准

### NFR-1 常驻开销（硬指标）

1. **空转（收起态、鼠标远离）**：单核占用中位 ≤ 3%（对照：不改那条呼吸动画时实测 15–18%/核，`probe:3-5`、`probe:111-121`）；整机占用 ≤ 3%。
2. 呼吸动画是第一刀：降频到 2fps 或去掉后实测 0–2%/核（`probe:118-119`）；**这条与栈无关**——编译版带着同一条动画同样是 15.2%（`probe:206`）。
3. 拖动期不劣于原型基线：原型实测 25–37%/核（整机 ~1.6–2.3%），`spike:68`。

**度量方式**：真机探针 5 分钟采样（照 `probe` 的测量方法：进程 `TotalProcessorTime` 增量 / 墙钟，不带渲染钩子，`probe:90`、`probe:133`）；拖动场景单跑一次。

### NFR-2 启动与内存

窗口可见中位 ≤ 0.6 秒、工作集 ≤ 200MB（对照实测：编译版 0.351s / 122MB；PowerShell 版 1.707s / 326–344MB，`probe:142`、`probe:150-154`）。

**度量方式**：真机 5 次启动采样 + 稳定后 60 次内存采样（`probe:90`、`probe:146`）。

### NFR-3 依赖与构建可追溯（硬要求）

1. 零第三方依赖：只用系统自带的 .NET Framework 编译器与运行时程序集，无 MSBuild / NuGet / 联网下载（`probe:33-34`）。
2. 语法上限 **C# 5**（实测 C#6/7 全挂：`$"…"` / 自动属性初始化 / `out var` / 模式匹配 / 元组，`probe:45-50`）。
3. exe **不进 git**，只在冻结提交上构建；来源保底 = **提交 + 编译器 + 出厂 SHA256**（exe 不是字节可复现：PE 时间戳 + MVID 共 17 字节差异，`probe:76`）。
4. 绝不允许把开发目录里编好的 exe 打进包（`probe:176`）。

**度量方式**：设计档 3.3 A1 / A3（来源记录核对 + 冻结树构建 + 开发目录不含 exe）。

### NFR-4 不打扰（窗口纪律）

逐像素透明（形状外面就是桌面）、置顶、不抢焦点、不占任务栏按钮、收起态点击穿透、展开态与微型不穿透（`spike:6-7`、`spike:70`、`probe:59-65`）。

**度量方式**：OS 层读回窗口扩展样式 + 跨边缘像素逐通道比对 + `WindowFromPoint` 读数（照 `probe` 的读回做法，`probe:53-65`）。

### NFR-5 用户数据（位置记忆）

位置与形态写用户数据目录（`%LOCALAPPDATA%` 下的面板状态文件）：**不写仓库、不写安装目录**；读不到 / 坏掉 → 回默认位置且不报错不弹窗（`spike:14`、`spike:16`、`lib §4.10`）；卸载时的去留与既有数据处置口径一致。

**度量方式**：设计档 3.3 A7（坏文件夹具 + 重启复位 + 夹回可见区）。

### NFR-6 文案极简（用户铁律）

面板可见文本只有固定词表范围内的数字与标签（`5h 还剩` / `7 天 还剩` / `余额` / `今天 · 这个项目` / 状态四态 / `数据` / `刷新` / `已过` / `1 圈 = ¥X` / `—` 等）；不出现解释性句子；单位说明只在换过单位时出现（`spike:41`）。

**度量方式**：设计档 3.3 A11（自检输出上屏文本清单，与词表比对）。

### NFR-7 可访问性

系统开着「减少动态效果」时：三处动画（变形 / 回贴边 / 反馈退回）与读数扫动**全部走瞬时**，功能一项不差（实测：变形 0ms / 0 帧、回贴边无动画、跟随误差 0.0 DIP，`spike:68`）。

**度量方式**：设计档 3.3 A10（自检夹具强制开/关该开关各跑一遍）。

### NFR-8 项目纪律

1. 新增 `.vbs` 保持**纯 ASCII**（Windows 脚本宿主按 ANSI 代码页读取，中文注释会破坏解析；`README.md` 已知边界一节）；
2. 不改采集器 / 规则引擎 / 数据层存储格式；
3. 发布仍走三层文件模型（L1 开发 / L2 发布 / L3 安装），新增产物必须显式归类；
4. 面板不读密钥（不碰 `secrets.json`、不碰 Codex 的 `auth.json`），只读看板数据文件与 ThinCoder 自己的会话/进程文件。

**度量方式**：设计档 3.3 A15 / A2 + 代码走查（设计档 2.5）。
