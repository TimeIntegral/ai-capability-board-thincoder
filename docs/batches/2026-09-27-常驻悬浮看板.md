## §1 批次说明（主 agent 撰写）

### 1.1 为什么做这一批

看板目前只有一种看法：**打开浏览器**。而看板的核心用户是「正在用 ThinCoder 写活的人」——他不想为了看一眼额度去切窗口、开浏览器、再切回来。

用户已经把这件事用原型走完了：`private/spike/` 里有一份真机验证完毕的悬浮原型（中型边缘胶囊 + 微型小卡片 + 余额圈），形态、交互、口径、阈值、动画参数都逐条验收过（见 1.3 与设计档 2.2.12）；`private/stack-probe/` 把「能不能编译成 exe」「开销到底花在哪」「发布链要动几处」「升级会不会装不上」四个问题一次测完。

用户 2026-09-27 拍板：**按编译版 exe 落产品化**，第一刀先改那条呼吸动画，形态与交互照原型，口径一条不许丢，发布链与升级收口按探针清单做。
本批就是把这件事按项目规矩落档（需求 / 设计 / 批次三档），然后实现。

**定位依据（用户原话）：「一定要紧密结合 ThinCoder 的功能。这才是我们的灵魂。」**——面板的两档内容都围绕 ThinCoder 的实时状态与项目轮次组织（见需求档 US-5 / US-6）。

### 1.2 本批要做的（需求摘要）

用户可见的行为：

| # | 用户看到什么 |
|---|---|
| 1 | 屏幕边缘一条极窄的条（**与展开面板同高**）：鼠标一靠就展开，移开立刻收回；收起时鼠标直接穿过它 |
| 2 | 面板上：Codex 5h / 7 天「还剩多少」+ 各自刷新时间、余额圈、今天·这个项目、状态四态 |
| 3 | 桌面上一张小卡片（228 × 90）：状态 + 项目名 + 会话时长 + 最紧的额度环 + 最紧一家的余额圈 |
| 4 | 展开的面板往外拖就变小卡片；小卡片拖到任意一边附近松手就贴回那条边，落点就是松手的位置 |
| 5 | 关掉再打开还在原处（形态 + 边 + 位置）；屏幕变小也「能修就修」，从不静默丢弃 |
| 6 | 数据旧了只有读数变暗，状态永远实时；数字变化 240ms 扫过去，不跳变 |
| 7 | 装完就能用、升级能正常覆盖（运行中的面板会被自动停掉再换文件）、卸载能清干净 |

### 1.3 已知事实（勘察结论，设计不必重新探索）

**A. 原型（`private/spike/`，真机验证完毕；出处见设计档 2.2.12）**

| 项 | 结论 |
|---|---|
| 形态 | 中型胶囊（收起条 8 DIP 宽、与展开同高、热区 34 DIP、悬停展开、移开 150ms 防抖即收）+ 微型卡片 228 × 90；四条边都支持；内容不转 90°（`spike:6`、`spike:10`、`spike:12`） |
| 拖动转换 | 拉离贴边 ≥36 DIP → 微型；离边 ≤64 DIP 松手 → 中型贴最近边、沿边落点 = 松手位置；拖动起点只在展开态（`spike:8`） |
| 窗口 | 逐像素透明（形状外即桌面）、置顶、不抢焦点、不占任务栏；收起态穿透、展开态与微型不穿透（`spike:70`、`spike:72`） |

| 位置记忆 | `%LOCALAPPDATA%` 下的状态文件；坏文件回默认、不弹窗；坐标夹回可见区；只支持主屏（`spike:14`、`spike:16`） |

**B. 栈实测（`private/stack-probe/`，一次实验、不是产品）**

| 项 | 结论 |
|---|---|
| 能不能编 | 系统自带 .NET Framework 4 编译器可以编出可运行 WPF exe；不需要 targeting pack / MSBuild / NuGet / 联网；编译 158–185 ms（`probe:31-35`） |
| 语法 | 天花板 **C# 5**（C#6/7 全挂）（`probe:45-50`） |
| 窗口属性 | 编译产物 OS 层读回：透明 / 穿透 / 置顶 / 不抢焦点 / 不占任务栏（`probe:52-65`） |
| 可复现 | **不字节可复现**（PE 时间戳 + MVID 共 17 字节）；方法 IL 23/23 相同（`probe:76`） |
| 开销真相 | 15–18%/核 是那条呼吸动画：连续动画 = 每帧整窗重绘；降到 2fps → 0–2%；去掉 → 0–1.5%；**与栈无关**（编译版带同一条动画 15.2%）（`probe:111-125`、`probe:206`） |
| 启动 / 内存 | 编译版 0.351s / 122MB；PowerShell 版 1.707s / 326–344MB（`probe:142`、`probe:150-154`） |
| 发布链 | 要动四处：`publish-files.mjs`（构建时加入加 exe 条目）、`publish.mjs`（照 `inspectRuntime()` 加来源核对 + 塞进 zip）、`test-publish-files.mjs`（两处断言）、`prepare.mjs`（冻结提交里编译 + 候选快照记哈希）；`build-installer.mjs` 不用改（`probe:160-169`） |
| 升级收口 | **硬卡点**：运行中的 exe 锁自己的镜像 + 安装器 `CloseApplications=no` → 不修就装不上；三处针：`stopOwned()` 按 exe 路径匹配、`install.mjs` 装完拉起、`uninstall.mjs` 清理（`probe:181-193`） |
| 未覆盖 | 拖动期开销、降频观感、发布链改动实跑、SmartScreen、多屏/DPI、csc 在别的机器、状态文件与卸载清单对齐（`probe:216-227`） |

**C. 本仓现状（设计直接引用，不必再探索）**

- 发布三层模型：L1 开发层（git 跟踪 + 未忽略的未跟踪文件，`publish.mjs:73-87`）/ L2 发布层（`publish-files.mjs` 正列举）/ L3 安装层（`从stage推导()` 推导，`build-installer.mjs:39-78`）；二进制不逐行审计、走来源核对（`publish.mjs:447-469`）。
- `prepare.mjs` 的冻结机制：工作区干净才动手 → `git worktree add --detach` → 之后所有构建都在冻结树里跑（连 `runtime/` 都是复制进去的），最后把 zip/exe/latest.json/SHA256SUMS + `release-snapshot.json` 收进 `dist/candidate-*`。
- 系统集成的收口现状：`windows-integration.mjs:51-56` 只认两种进程（托盘 `powershell.exe` + 运行时的 `node.exe`）；安装器 `installer.iss:31-32` 两个 `no`；托盘「装完拉起」的先例在 `install.mjs:140-145`；卸载的用户数据清单与安装器删除分支是**同一份**且有测试对一遍（`uninstall.mjs:15`）。
- 数据面：`dashboard-data.js` 里 `codex.atMs` / `codex.fiveHour.usedPercent` / `codex.weekly.usedPercent` / `deepseek.totalBalance` / `glm.balance` / `generatedAtMs` / `cards.<平台>.show` 都在（本次实读）；看板显示开关 `dashboard.html:657` 的 `platHidden` 读的就是 `cards`；ThinCoder 侧数据在 `%USERPROFILE%\.thincoder`（会话槽位 / agent 日志 / peers 心跳）。

### 1.4 勘察发现的缺漏（设计必须处置；出处见括注）

| # | 缺漏 | 说明 | 严重度 |
|---|---|---|---|
| 1 | **升级针不存在（硬卡点）** | 运行中的面板 exe 会锁住自己的镜像文件；安装器 `CloseApplications=no` → 覆盖安装会失败。现有收口不认任何编译出来的 exe（`probe:181-192`） | 🔴 高 |
| 2 | **exe 不在三层清单里** | 新产物没归类 → 发布闸门会直接停下；且 exe 不能进 git（否则 `prepare.mjs` 的干净检查与「二进制不逐行审计」两条纪律打架）（`probe:166`、`probe:177`） | 🔴 高 |
| 3 | **发布链测试写死了「构建时只有 runtime」** | `test-publish-files.mjs:86/90` 两处断言，不改就红（`probe:168`） | 🟡 中 |
| 4 | **面板状态文件与卸载清单没对齐** | 卸载时留不留位置记忆文件：两侧清单（`uninstall.mjs` 用户数据 / `installer.iss` 删除分支）+ 契约测试都要同改（`probe:227`） | 🟡 中 |
| 5 | **exe 不是字节可复现** | 不能拿「重编一次哈希相等」当验收；只能记来源（提交 + 编译器 + 出厂 SHA256）（`probe:76`） | 🟡 中 |
| 6 | **拖动/展开期开销在编译版未实测** | 探针只测了空转；原型 25–37%/核 是 PowerShell 版读数（`probe:220`） | 🟡 中 |
| 7 | **面板的开关 / 退出入口没定** | 装完一直在，用户要关掉时怎么办？未拍板（设计档 2.6 open-3） | 🟡 中 |
| 8 | **多屏 / 非 100%·150% DPI 未测** | 本批只支持主屏；其它 DPI 的几何要实测（`probe:224`） | 🟡 中 |
| 9 | **csc 在别的机器上是否都在** | 前提是「Windows 10/11 + .NET Framework 4.x」；用户机可能只装 .NET 4.8 运行时（`probe:225`） | 🟡 中 |
| 10 | **未签名 exe 的首启体验未测** | SmartScreen / 杀软会不会拦，本机没测（`probe:223`） | 🔵 低 |
| 11 | **空态字面没落到文档** | ThinCoder 未装 / 数据文件缺失时的空态：原型有对照图，README 未逐张说明（设计档 2.6 open-7） | 🔵 低 |
| 12 | **JSON 解析路径未验证** | 本机 .NET Framework 目录里 `System.Web.Extensions.dll` 与 `System.Runtime.Serialization.Json.dll` 都在（本次实读），但「引用哪一条、C# 5 下能否编过」没测（设计档 2.6 open-6） | 🔵 低 |

### 1.5 明确的边界（不做的事）

- 不做多屏、不做跨屏拖动（只支持主屏）；贴上/下边时内容不转 90°。
- 拖动起点只在展开态（收起条是穿透热区）。
- 面板不做自己的设置界面、不接收输入（口径随 `config.json` 与看板；避免第二个配置真相源）。
- 不引入服务端 / 监听端口 / 第三方依赖；不联网。
- 不改采集器 / 规则引擎 / 数据层存储格式；面板不读密钥（`secrets.json` / Codex 的 `auth.json`）。
- 不做字节级可复现构建。
- 不改 `private/spike/` 与 `private/stack-probe/` 里的任何文件（只读引用）。
- 开机自启不在本批（未拍板）；`CHANGELOG.md` 与 `README.md` 由主 agent 落笔。

### 5.2 与设计档不一致的三处（照实登记）

1. **面板会读 `config.json` 的 `panel.enabled`**（每 5 秒一次，只读这一个字段）：设计档 2.1.4 说面板只读 `dashboard-data.js` 与 ThinCoder 文件。三处开关要能「关掉就不能自己回来」，这个开关必须有真相源，而它非 `config.json` 莫属（K11：面板不做自己的配置）——因此面板多了一个「只为自己开关」的读面。它**不读** `secrets.json` / `auth.json`（T19 机判）。
2. **面板状态文件的卸载清理走 `uninstall.mjs`（`stopOwned(remove)`），不走 `installer.iss`**：该文件在 `%LOCALAPPDATA%\AICapabilityBoard\`（用户数据目录），安装器的 DelTree 只能删安装目录里的东西，本来就不该、也碰不到它。设计档 2.2.10 已同步改正。
3. **余额段家数变化时重建整段布局**（原型只重建圈行）：口径「看板里关掉的平台整组不出现」包含面板高度的三档（328/410/466），家数变了高度得跟着走。这是原型没有的路径，按同一套口径补上。
