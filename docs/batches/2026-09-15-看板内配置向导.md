## §1 批次说明（主 agent 撰写）

### 1.1 为什么做这一批

公开版即将发布，目标用户里有相当一部分不懂技术。实测（用沙箱当新用户跑过一遍完整路径）暴露的核心问题是：

**新用户不知道怎么配置。** 具体表现：

1. 装完不知道成没成——安装脚本只说"全部完成"，不验证是否真采到数据
2. 不知道要建 `secrets.json`——这个文件不存在，得跑一次采集读控制台、或打开看板才知道
3. 不知道该开哪几个平台——默认三个全开，只用到一两家的人会一直看到"未配置"
4. 配置入口分散在三处——平台开关在 `config.json`、密钥在 `secrets.json`、阈值在看板工具区

现有的兜底是控制台向导（`首次配置.bat` → `tools/setup.mjs`）。用户明确要求：**能不能在看板里配？** 不要弹控制台。

实测确认技术可行（见 1.4），本批把配置搬进看板。

### 1.2 本批要做的（需求摘要）

**主需求**：在看板里提供一条完整的首次配置路径，不依赖控制台窗口。

用户可见的行为：

| 步骤 | 用户看到什么 |
|---|---|
| 1 | 打开看板（还没有数据）→ 看到引导，第一句就是"开始配置" |
| 2 | 选要监控哪些平台（Codex / DeepSeek / GLM）——按探测结果给建议 |
| 3 | 对需要密钥的平台填密钥（输入不回显） |
| 4 | 点保存 → 用户选一次项目文件夹 → 页面自己写好密钥文件 |
| 5 | 页面触发一次采集，把每个平台的结果显示在同一页 |
| 6 | 明确告诉用户"成了 / 还差什么"，以及怎么让它自动运行 |

**次要需求**：让"它自动运行"这一步也在看板里有明确交代（见 1.4 第 2 条缺口）。

### 1.4 勘察发现的缺漏（用户要求"看看有没有缺漏"）

按严重度排列。前两条是设计必须解决的**真缺口**，其余是必须覆盖的边角。

| # | 缺漏 | 说明 | 严重度 |
|---|---|---|---|
| 1 | **`secrets.json` 已存在时可能被覆盖** | 用户可能已有其中一家的密钥（比如先配了 DeepSeek 再配 GLM）。写入必须**合并**，不能整份覆盖，否则丢掉另一家的密钥 | 高 |
| 2 | **看板内无法注册计划任务** | 写配置可以（协议 / 文件写入），但注册计划任务必须跑 `tools/install.mjs`（要起进程）。**本批必须给出"配置完成后如何进入自动采集"的明确路径**，不能配完就断在那 | 高 |
| 3 | **浏览器能力差异** | File System Access API 只有 Chromium 系支持。不支持时必须**明确提示并给兜底路径**，不能让按钮点了没反应 | 高 |
| 4 | **密钥的生命周期** | 密钥在页面内存期间不得落入任何持久化存储（localStorage / IndexedDB / console / DOM value 残留）；输入框 `type=password` + `autocomplete=off`；写完后立即清空 | 高 |
| 5 | **选错文件夹** | 用户可能在文件夹选择器里选错目录。必须校验选中目录里确实有本项目（如 `collect.mjs`），选错就明确拒绝并让重选，绝不写到别处 | 高 |
| 6 | **权限句柄失效** | 存进 IndexedDB 的目录句柄在文件夹被移动 / 删除 / 换机器后失效，要能优雅降级回"重新选择" | 中 |
| 7 | **两个入口的职责重叠** | 现在配置面板里的"运行配置向导"走控制台。新的看板内向导上线后，两者关系要理顺，避免用户面对两个都能配的地方 | 中 |
| 8 | **写配置是异步生效的** | 协议写 `config.json` 后，页面上的状态要等下一次采集才更新。必须给"已提交，约 1 分钟后生效"这类明确反馈，并说明怎么立刻看到结果 | 中 |
| 9 | **试采结果的反馈方式** | 保存后触发采集（协议 `collect`），但页面无法读取文件、也不知道采集何时结束。要定义"等待中 → 结果"的 UX 与超时处理 | 中 |
| 10 | **`showNoData()` 文案过时** | 它仍然叫用户去双击「安装定时任务.bat」并手动改 `config.json`，与本批的新路径冲突 | 中 |
| 11 | **Codex 不填密钥** | Codex 的凭据来自登录文件，向导**不能**问用户要 Codex 的密钥；要沿用已有的分平台提示 | 低 |
| 12 | **测试文档缺失** | 工程要求每条用户故事至少对应一个测试用例；本仓目前只有 `tools/test-rules.mjs`（规则引擎），没有测试文档 | 中 |

### 1.5 明确的边界（不做的事）

- **不删控制台向导**：`首次配置.bat` / `tools/setup.mjs` 保留为兜底路径
- **不引入任何服务端 / 本地监听端口**：密钥不经 URL 传递（会进进程命令行与 `protocol.log`），也不起 HTTP 服务
- **不引入第三方依赖**：项目零依赖是硬约束
- **不改采集器 / 规则引擎 / 数据层**：本批只动看板、协议与配置写入侧
- **不做多文件夹 / 多项目管理**：只服务"本机这一个项目目录"

### 实施要点（关键机制，细节见设计档）

1. **写通道**：页面直写（File System Access 目录句柄）。用户选一次项目文件夹 → 校验（`collect.mjs` + `dashboard.html` 同时在）→ 合并写 `secrets.json` / `config.json`（`{...既有, ...新填}`，未知字段保留，写完回读核对）。密钥**永不**进 URL / iframe src / 进程命令行 / 日志 / 存储 API。
2. **动作通道**：`运行协议.vbs` 新增两个分支（纯 ASCII）：`setupcheck` → `node tools/setup-check.mjs`；`setupinstall` → `node tools/install.mjs --skip-verify`。动作固定、无参数。
3. **读通道**：新增 `tools/setup-check.mjs` 写 `data/setup-status.json`（字段契约见设计档 2.2.3；只含状态与来源标签，无密钥值），页面经目录句柄读；试采结果走既有 `dashboard-data.js` 轮询。
4. **首次启用（缺漏 2 的答案）**：双路径——系统侧已启用（协议已注册）时向导内一键安装；全新副本（协议未注册）引导双击新增的静默脚本 `启用自动采集.vbs`（隐藏运行、无控制台窗口、末尾 ASCII MsgBox 反馈）。开启状态一律以 `schtasks` 实查为准。
5. **安全纪律**：密钥只在 password 输入框 → 单个临时对象 → 立即写盘 → 立即清空 / 释放；渲染与提示只用「来源 / 长度」；坏文件用显式「备份并重建」（先写 `data/<名>.broken.bak`）。
6. **测试机制**：`tools/test-dashboard.mjs`（新增）把 `dashboard.html` 复制到临时目录 + 注入测试引导脚本（插桩 / 桩 `showDirectoryPicker` / 短超时 / 真实点击驱动），
   用 `--headless=new --virtual-time-budget --dump-dom` 回读结果节点后断言；**不得依赖 IndexedDB**（无头 `file://` 下 `indexedDB.open` 回调实测不返回）。
   原生文件夹选择器无法自动化——真实选择器 + 真实落盘、真实安装、真实试采、句柄持久化、Firefox 兜底 = 人工验收步骤（设计档 3.4 共 12 步）。
