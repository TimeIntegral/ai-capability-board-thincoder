# 本地 AI 能力看板

## 下载并开始使用

面向 ThinCoder 与多模型用户的本地 AI 用量看板：集中查看 Codex、DeepSeek、GLM 的额度、趋势和提醒。

**Windows 10 / 11 · x64 · 无需安装 Node 或 Git。**

1. [下载 Windows 安装版](https://github.com/TimeIntegral/ai-capability-board-thincoder/releases/latest)——选择名称以 `windows-x64-setup.exe` 结尾的附件。
2. 双击安装，完成后打开看板，点击「开始配置」。
3. 打开本机连接窗口，选择平台；已有账号自动复用，缺少的 API Key 粘贴一次，点击「保存并验证连接」。

想解压即用，可以选择同一发行版中的便携 ZIP，解压后双击「快捷操作 → 启动看板.vbs」。GitHub 自动生成的 Source code 仅供开发使用，不含运行环境。

- **用便携 ZIP 覆盖升级的，升级后请双击一次「快捷操作 → 安装定时任务.bat」**：安装版升级会自动把自动采集重新接好，覆盖解压不会——自动采集还在按升级前的位置找程序文件（那些文件已经挪进「程序」），表现是看板能打开、数字却不再更新。双击一次即可，配置和历史都不受影响。

**一句话定位**：一个**零外部依赖**的 Windows 本地看板——把 Codex / DeepSeek / 智谱 GLM 三家的额度与用量集中到一处，数据全部来自本机。

**它解决什么**：官方用量页只回答「还剩多少」；本地看板回答只有你自己的数据才能证明的三件事——**额度被哪个项目吃掉了**、**实际在用哪个模型**、**照当前速度多久触顶**。

## 它和官方看板有什么不同

| 维度 | 各家官方用量页 | 本地 AI 能力看板 |
|---|---|---|
| 覆盖面 | 一次看一家，口径各不相同 | 三家同屏：一套采集、一套时间窗、一套告警 |
| 视角 | 平台想让你看到的那一面 | **只有本地数据能证明的**：按项目归因的额度去向、模型使用轨迹、跨平台消耗对比 |
| 时间跨度 | 通常只有当前窗口 / 最近几天 | 本地历史**永久保留**（分级降采样），可回看 30 天 / 全部 |
| 主动性 | 无（或只发邮件） | 场景化 Windows 通知：触顶预测、异常消耗、余额告急、采集异常…… |
| 数据位置 | 数据在平台 | 数据全在本机 `data/`：无云端、无遥测、凭证只读 |

## 特性

### ① 额度去哪了（只有本地数据能给的视角）

- **额度去向（Codex 会话归因）**：解析本地 `~/.codex/sessions/` 的会话记录，按**项目目录**聚合 token 用量，回答"额度被谁吃掉了"——这是官方页面给不了的信息。六列表格（项目 / ThinCoder / 用量 / 占比 / 文件夹 / 启动），幅度用整行色带表示；可切 **近 7 天 / 近 30 天 / 全部历史**，所有项目一次列出（面板内滚动）。
  - **ThinCoder 列**：用过 ThinCoder 的项目显示绿色 `⌨ N` 徽标（N = 会话数），其余为淡点——竖向扫一列就知道哪些项目用过。判定依据是 `~/.thincoder/sessions/` 里会话文件记录的 `cwd`。
  - **点击跳转**：`📁 打开` 在资源管理器打开该项目目录；`⌨ 启动` **在该项目目录启动 ThinCoder 工作台**（仅该项目用过 ThinCoder 时可用，其余显示横杠）。两者各占一列，路径经白名单校验后才执行。
- **AI 能力构成（模型使用画像）**：从本地会话每轮的模型记录聚合你**实际使用的模型**——接口只告诉你"哪些模型可用"，这里回答"在用哪个、用在哪、什么时候换的"。七列：模型 / 调用次数 / 用量 / 占比 / **活跃区间**（首次→最近使用，一眼看出模型切换轨迹）/ 主要用在 / 当前可用标记；表头可排序。
  - 卡片下方附**使用方式画像**：权限模式（全放权 / 按需确认）、沙箱策略、推理强度分布，以及**平均每轮消耗**的 tokens——回答"我实际是怎么用它跑活的"。
  - **口径**：模型表的「调用」是 API 调用次数，不是任务回合数（一次任务回合平均触发约 10 次调用）。
- **ThinCoder 项目**：独立区块列出**所有用过 ThinCoder 的项目**（含只用了 ThinCoder、没用 Codex 的那些）——项目名、所在目录、**会话数 / 轮次 / 最近使用**，可切近 7 天 / 近 30 天 / 全部；每行可 `📁 打开` 文件夹、`⌨ 启动` ThinCoder 工作台。
- **表格排序**：上述三张表格的**表头可点击排序**（再点一次反向，当前列高亮并显示 ▾/▴）；数值列默认降序、名称列默认升序，中文按拼音序。

### ② 现在还剩多少、多久会见底

- **实时状态**：三平台指标卡 + 趋势曲线（带蓝色标记）。**Codex 以「剩余额度」为口径**——卡片、状态条、曲线、提醒文案一律显示「剩余 X%」（悬停/卡片同时给出已用百分比）；曲线纵轴为剩余额度，告警线画在剩余 20% 处。
- **区间选择统计**：在任意趋势图上**点两下选择区间**（第一下起点、第二下终点；第三下重新开始，`Esc` 或「清除」取消），下方即给出该区间的统计——Codex 显示「5h 峰值/平均已用、≥阈值时长、采样间隔、无采集时长」，余额图显示「余额变化、净消耗、日均消耗、按此速率可用天数」。选择会跨数据刷新保持。
  - 口径说明：Codex 的 `used_percent` 是**滚动窗口值**（不是只增不减的计数器），所以无法精确反推"这段时间消耗了多少额度"，只能给峰值/均值/超阈值时长；**余额类平台的金额是可精确求和的**（余额下降段之和 = 实际花费）。
- **余额变化拐点**：DeepSeek / GLM 余额图上，每个**变化起点**画竖线 + 圆点（下降橙、回升绿），卡片下方列出最近 4 次变化的起始时刻、金额与起止余额——回答"什么时候开始变的"。幅度小于余额 0.4% 的抖动不标记。
- **触顶预测**：按近 30 分钟的消耗斜率外推，预计 X 分钟内触顶时提醒（"照此速度约 42 分钟后触顶"）。
- **数据停滞可视化**：关机/离线等没有采集的时间段，曲线用**灰色虚线**连接（5h 窗口浅灰、7 天窗口深灰）并铺灰色底带；悬停在这些时段会提示「数据停滞（无采集）」。判定阈值＝超过 3 个采集间隔且 ≥10 分钟（余额类 ≥15 分钟）。

### ③ 历史与记录

- **每日热力图**：GitHub 风格日历网格（周 × 星期），带**星期轴（左）与月份轴（上）**，可定位到具体哪一周、哪一天；支持「Codex 用量峰值 / DeepSeek 消耗 / GLM 消耗」三种指标切换；颜色深浅=当天强度，空心格=无数据（未开始记录 / 关机离线），深色边框=今天，悬停查看当天数值。网格按卡片实际宽度铺满（**格子尺寸固定 20px，不拉伸**；数据不足时在左侧补空格子，8 周为下限）。
- **分区呈现**：「实时状态」（指标卡 + 趋势）与「历史与记录」（GLM 充值记录表 + 提醒流水，扁平列表样式）刻意做成两套视觉体系，便于快速区分；充值记录是**支付凭证**而非未消费额度，并带到期状态标记（有效 N 天 / N 天后到期 / 已过期）。
- **时间窗 / 主题**：右上角刷新进度环显示**距下次刷新还有多少秒**，可手动刷新；时间窗口支持 24 小时 / 7 天 / 30 天 / 全部；主题按钮三态循环（`自动·深/浅` → `深色` → `浅色`），**手动选择会持久保存，数据自动刷新不会重置它**（优先级：手动选择 > `config.dashboard.theme` > 跟随系统）。
- **永久保留**：默认不删除任何数据点，用分级降采样控制体积（见下文「数据保留」）。

### ④ 不用盯着看（提醒）

- **场景化提醒**：额度释放、5h / 周阈值、限流、余额告急与耗尽、订阅闲置、触顶预测、消耗异常、采集异常与降级恢复等（完整矩阵见下文）——每条通知都能点开看板。
- **降噪设计**：一次采集最多弹 **1 条**通知（多事件聚合）；阈值用 armed/滞回（穿越一次只报一次）；连接状态双向滞回（连续 15 分钟降级才报、30 分钟稳定才算恢复）；滞回按**分钟**配置——采集频率从 5 分钟改到 1 分钟时灵敏度不变（代码按各平台实际间隔换算样本数）。
- **免打扰与静音**：免打扰时段内 P1/P2 入队、时段结束后合并补发，P0 仍即时送达（无提示音）；临时静音在托盘菜单里（右键任务栏图标 →「静音 2 小时」）。
- **按平台的余额提醒开关**：某个模型不打算继续用了，但它的低余额提醒一直弹——在通知或看板余额卡上点「不再提醒」，**直到该平台充值（余额回升）自动恢复**（详见下文）。
- **采集健康**：每平台近 24 小时的成功率、采集次数、平均耗时与最近错误——数据存疑时可自证清白。

### ⑤ 装一次就不用管

- **一键安装**：`node 程序/tools/install.mjs`（或双击「快捷操作 → 安装定时任务.bat」）一条命令完成六步——计划任务、图标、桌面快捷方式、通知应用名、按钮协议、托盘自启；旧版本的残留任务与快捷方式会被自动清理。
- **定时采集**：计划任务按最小间隔触发（默认 1 分钟），开机自动恢复、错过的点补跑、睡眠不唤醒、隐藏运行、防并发重叠。
- **托盘常驻**：任务栏图标悬停显示三平台当前状态，右键可打开看板/立即采集/静音/退出，双击打开看板，随开机自启（不想要就把 `config.json` 的 `tray.enabled` 设为 `false` 后重跑安装）。
- **一键备份**：把全部历史与配置打包为 zip（自动轮转保留最近 N 份）——永久保留的数据有了导出出口。
- **平台跳转**：卡片标题旁的 `↗` 直接打开各平台官方用量/财务页（地址在 `config.json` 的 `links` 段可改），余额告急/耗尽的**通知上也带「去充值」按钮**。

### ⑥ 本地优先

- **凭证只读（采集运行时）**：运行时代码只**读**本机的 Codex `auth.json` 与 ThinCoder 配置里的 API Key，不落盘、不进日志、不进 git；错误信息统一脱敏（避免 token 经 state 流入看板）。**看板页面不接触密钥值**：独立本机连接窗口接收密钥，经标准输入交给本机程序保存；不经网页、URL、命令参数或日志。自动复用 ThinCoder / 现有本机密钥 / 环境变量，无需额外安装 ThinCoder。
- **动作白名单**：看板与通知上的按钮经自定义 URL 协议 `aiquotaboard://` 执行，打开文件夹、启动项目、修改配置都先过白名单与区间校验，越界一律拒绝并记日志。
- **零外部依赖**：没有 `node_modules`，只用 Node 内置 API 与 Windows 自带能力（PowerShell / `wscript` / 系统 `curl`）。

## 快速开始

**前置条件**

| 需要 | 说明 |
|---|---|
| Windows 10 / 11 | 计划任务、托盘、toast 通知、`wscript`、系统 `curl` 都是 Windows 组件 |
| Node.js ≥ 20.11 | 用到 `import.meta.dirname`（开发与验证环境为 v24）。**无需 `npm install`**——无任何第三方依赖 |
| Codex（可选） | 装了并登录过，才能采集 Codex 额度（token 复用 `~/.codex/auth.json`，由 Codex 自动续期） |
| ThinCoder（可选） | DeepSeek / GLM 的 API Key 与「ThinCoder 项目」区块从这里读（`~/.thincoder/config.json`） |

**步骤**

> ### 最省事的方式：安装版 → 开始配置 → 打开连接窗口
>
> 勾选平台，已有账号自动复用；缺少的 DeepSeek / GLM API Key 粘贴一次，点「保存并验证连接」。Codex 在客户端登录即可。成功后自动采集，失败的平台可稍后重试。
>
> Codex 展示订阅额度；DeepSeek / GLM 展示 API 余额，不能据此推断聊天订阅或 Coding Plan 额度。
>
> 以下为高级手动配置说明。开发目录不允许注册后台任务或安装更新，日常使用请安装独立发行版。

1. **把项目放到本机任意可写目录**（`data/`、`backups/` 会持续写入）。

2. **复制配置**（用安装版的「开始配置 → 本机连接窗口」配过的话，`config.json` 已经生成，可跳过复制）：

   ```bat
   copy config.template.json config.json
   ```

   打开 `config.json`，至少改这几项：

   | 配置项 | 改成 |
   |---|---|
    | `codexHome` | 你的 Codex 目录，通常 `%USERPROFILE%\.codex`（留空 = 自动推导） |
    | `thinCoderConfig` | 你的 ThinCoder 配置，通常 `%USERPROFILE%\.thincoder\config.json`（留空 = 自动推导） |
    | `notify.launchUrl` | 本机 `dashboard.html` 的 `file:///` 地址（留空 = 自动指向本机 dashboard.html） |
    | `projectsRoots` | 「额度去向」允许打开的项目根目录白名单（如 `["%USERPROFILE%\\projects"]`）；留空则只能打开本项目目录，写错会导致点击被拒绝 |

   其余字段留空即用默认值（阈值、滞回、冷却、免打扰、保留策略……见下文「配置」）。

3. **试跑一次采集**：

   ```bat
   node 程序/collect.mjs
   ```

   首次会创建 `data/` 并写入 `state.json`，控制台打印三平台取数结果与提醒判定。忽略间隔强制全采：`node 程序/collect.mjs --all`。

4. **跑一遍规则测试**（可选，确认环境正常）：

   ```bat
   node 程序/tools/test-rules.mjs
   ```

5. **安装**（计划任务 + 图标 + 桌面快捷方式 + 通知应用名 + 按钮协议 + 托盘自启）：

   ```bat
   node 程序/tools/install.mjs
   ```

   等价于双击「快捷操作 → 安装定时任务.bat」。装完采集就按间隔自动运行了。

6. **打开看板**：双击桌面的「AI 能力看板」快捷方式，或直接双击项目里的 `dashboard.html`。
   想卸载：双击「快捷操作 → 卸载定时任务.bat」（只删计划任务，看板与数据保留）。

**常用命令**

| 命令 | 用途 |
|---|---|
| `node 程序/collect.mjs` | 立即采集一次（`--all` 忽略间隔强制全采） |
| `node 程序/tools/install.mjs` | 一键安装 / 修复（计划任务、图标、快捷方式、协议、托盘） |
| `node 程序/tools/test-rules.mjs` | 规则引擎测试（回归用例 + 真实历史回放 + 降采样 + 预测/异常 + 配置白名单 + 向导契约；`--slow` 单跑真机不外泄扫描） |
| `node 程序/tools/test-dashboard.mjs` | 看板桩测试（无头浏览器 + 假目录句柄；需 Edge/Chrome，属重 IO） |
| `node 程序/tools/set-task-interval.mjs` | 改完 `intervals` 后同步计划任务触发间隔 |
| `node 程序/tools/attribution.mjs` | 单独跑一次额度归因（`--rebuild` 清空增量缓存全量重建） |
| `node 程序/tools/backup.mjs` | 立即备份（把历史与配置打包为 zip） |
| `node 程序/mute.mjs 30m` / `status` / `off` | 临时静音 / 查看 / 取消 |
| `node 程序/balance-mute.mjs suppress glm` / `off glm` / `status` | 按平台关闭余额提醒 / 恢复 / 查看 |
| `node 程序/tools/open-path.mjs <路径> --dry` · `node 程序/tools/open-tc.mjs <路径> --dry` | 试运行看板里的「打开文件夹 / 启动项目」动作（校验路径是否在白名单内） |

**日志与历史**：`data/collect.log`（采集日志，超 5MB 轮转）；通知失败记录 `data/notify-errors.log`；按钮协议记录 `data/protocol.log`。改动历史见 [`CHANGELOG.md`](CHANGELOG.md)。

## 余额提醒开关（按平台，「不再提醒」直到充值）

场景：某个模型你不打算继续用了，但它的低余额提醒会一直弹。

- **触发方式**（三处等价）：通知上的「不再提醒XX余额」按钮 · 看板余额卡上的同名按钮 · 命令行 `node 程序/balance-mute.mjs suppress glm`
- **恢复条件**（自动）：该平台**余额回升 ≥ ¥0.01**（即充值到账）→ 下次采集自动解除并恢复提醒
- **手动恢复**：看板上的「恢复提醒」按钮 · `node 程序/balance-mute.mjs off glm` · `node 程序/balance-mute.mjs off all`
- **查看状态**：`node 程序/balance-mute.mjs status`

实现：`data/balance-mute.json` 记录 `{平台: {抑制时刻, 当时余额}}`；规则引擎跳过被抑制平台的余额提醒（**余额与消耗速率仍照常采集与展示**，只是不弹通知）；`程序/collect.mjs` 每次采集比较当前余额与抑制时的余额，检测到回升即自动解除。

> 按钮依赖自定义 URL 协议 `aiquotaboard://`（由 `node 程序/tools/install.mjs` 或 `node 程序/tools/register-protocol.mjs` 注册；未注册时按钮点击无效，用上面的命令行替代）。

## 数据源与口径（重要）

| 平台 | 数据源 | 性质 | 稳定性预期 |
|---|---|---|---|
| Codex | `chatgpt.com/backend-api/codex/usage`（OAuth token 来自 `~/.codex/auth.json`） | 官方后端接口（未在公开文档中列出，但 Codex 客户端自身使用） | 高；token 过期后需开一次 Codex 使其自动续期 |
| Codex（降级） | `~/.codex/sessions/**/rollout-*.jsonl` 尾部的 `rate_limits` 快照 | 本地文件解析；实时接口不可达时自动启用 | 快照仅在使用 Codex 时更新（看板标注快照延迟） |
| DeepSeek | `api.deepseek.com/user/balance` | 官方公开文档接口 | 高 |
| 智谱 GLM | `www.bigmodel.cn/api/biz/account/query-customer-account-report`（API Key 鉴权）+ `/biz/recharge/user-recharge-list` | **非公开 web 接口，前端代码逆向**；官方可能随时改动 | 中——失效时看板显示「数据陈旧」并弹提醒，不会用旧值冒充 |

**网络**：Codex 需要代理（Node `fetch` 不走系统代理，改用系统 `curl`：先试配置/系统代理，失败再试直连，兼容 TUN 模式）；DeepSeek / GLM 直连。响应超时 12 秒，单次运行远小于触发间隔。

**密钥**：看板里的**配置向导不接触密钥值**（页面没有密钥输入框，也不读不写 `secrets.json`，只报「有没有、从哪来」）；采集运行时只**读**（从 Codex 的 `auth.json` 与 ThinCoder 配置、以及兼容路 `secrets.json` / 环境变量读取，不落盘、不进日志、不进 git），错误信息统一脱敏。

**额度去向的数字从哪来**：解析会话文件里每轮的 `cwd`（这一轮属于哪个项目）与 `token_count` 的 token 用量，按项目目录聚合。会话文件是只追加的，因此用**增量扫描**——每个文件缓存 `{大小, 已消费字节偏移, 按日聚合}`，下次只读新增的尾巴，文件没变大就完全不读：**首次全量约 10 秒（数百 MB 的会话文件），之后每次维护约 0.01 秒 / 0 字节**（只有正在写入的那个会话文件会读几十 KB）。

## Codex 额度口径（实测结论）

> 来源：对本地历史序列逐样本分析 `reset_at` / `used_percent` 的演化得出。

**`reset_at` 是「当前活动窗口的结束时刻」，不是滑动值。** 窗口从"上次窗口结束后你的第一次请求"开始计时；实测约 2/3 的相邻样本里 `reset_at` 完全不变（纯倒计时），只有约 1/5 跟随时间后移——后者全部出现在空闲期。

**空闲时会冻结。** 不使用 Codex 时不会开新窗口，`reset_at` 便一直停在过去（约 1/5 的样本即使已过期，中位过期约 20 小时），此时 `used_percent` 是那个**已结束窗口**的最终用量，而不是实时值。看板对这两种状态分别显示「HH:MM 刷新（剩 X）」与「窗口已结束（下次使用重新计时）」。

**5h 与 7d 是两个独立预算**，百分比各自相对自己的预算，**不能直接比大小**——约一半的样本「周已用 < 5h 已用」（5h 用到 60% 时周可能只有 9%），这在两个预算额度不同时是正常的，不是数据错误。

**因此规则引擎一律不依赖 `reset_at`**，只用用量走势（峰值回落 / armed 滞回 / 边沿）。这既避免了早期那类"每 5 分钟重复弹同一条提醒"的故障，也让空闲期的判定保持正确。

## 提醒场景矩阵

> 设计前提：Codex 的 `reset_at` 是**滑动窗口值**（≈ 查询时刻 + 窗口长度，每次查询都变），
> 不能作为"窗口身份"。因此规则只依赖「用量自身走势」：峰值回落 / armed 滞回 / 边沿。

| 场景 | 触发条件 | 级别 | 冷却 |
|---|---|---|---|
| 额度释放 | 用量从峰值 ≥60% 回落到 ≤20% 且降幅 ≥30pt | P1 | 4h |
| 5h 用量偏高 | 近 5h 用量 ≥80%（回落到 ≤75% 才重新武装） | P1 | 0.5h |
| 5h 用量临界 | 近 5h 用量 ≥95%（回落到 ≤92% 重新武装） | **P0** | 0.5h |
| 周用量偏高 | 近 7 天用量 ≥80% | P1 | 0.5h |
| 已限流 | `limit_reached` 由 false→true；持续期间按冷却重复提醒 | **P0** | 3h |
| 限流解除 | `limit_reached` 由 true→false | P1 | 3h |
| 余额耗尽 | 余额 ≤ ¥0 | **P0** | 24h |
| 余额告急 | GLM <¥2 / DeepSeek <¥10 | **P0** | 24h |
| 余额偏低 | GLM <¥5 / DeepSeek <¥20 | P1 | 24h |
| 实时接口降级 | 连续 15 分钟降级 | P1 | 24h |
| 实时接口恢复 | 降级后连续 30 分钟稳定 | P2 | 24h（与降级共用 key） |
| 订阅闲置 | 本地历史近 7 天 5h 用量峰值 <5% | P2 | 168h |
| 触顶预测 | 已用 ≥40% 且按近 30 分钟斜率外推 ≤30 分钟触顶 | P1 | 1h |
| 消耗异常 | 当日花费 > 近 7 日均值 ×3 且 >¥5 | P1 | 24h |
| 采集异常 | 某平台连续 15 分钟采集失败 | **P0** | 12h |
| 采集恢复 | 异常后连续 10 分钟成功 | P2 | 12h |

**降噪设计**：一次采集最多弹 **1 条**通知（多事件聚合）；阈值用 armed/滞回（穿越一次只报一次）；
连接状态双向滞回（连续 15 分钟降级才报、30 分钟稳定才算恢复）；滞回按**分钟**配置，
采集频率从 5 分钟改到 1 分钟时灵敏度不变（代码按各平台实际间隔换算样本数）。

**免打扰（23:00–08:00）**：P1/P2 入队、时段结束后合并补发；P0 仍即时送达（免打扰时无提示音）。
**静音**：静音期间 P1/P2 不弹（P0 由 `config.mute.allowP0` 决定），记录仍进提醒历史。

## 数据保留（默认永久）

**默认永久保留**，用分级降采样控制体积（`config.history.tiers`，每小时维护一次）：

| 数据年龄 | 粒度 | 量级 |
|---|---|---|
| 7 天内 | 原始（Codex 1 分钟 / 余额 5 分钟） | 约 1 万点/平台 |
| 7–30 天 | 5 分钟 | 约 6.6 千点 |
| 30 天–1 年 | 1 小时 | 约 8 千点 |
| 1 年以上 | 1 天 | 约 365 点/年 |

十年数据也只有几 MB（估算 <10MB/平台），且**不删除任何数据点**（每档按时间桶保留桶内最新样本）。
若想改为限量保留，把 `keepDays` 设为天数即可（>0 时超期数据才会被删除）。

看板通过「尾部读取 + 降采样」取数，长周期窗口（30 天/全部）走每小时生成的小型序列缓存，不会随时间变慢。

## 已知边界

- **Windows only**：计划任务、托盘、toast 通知、`wscript`、系统 `curl` 都是 Windows 组件；数据源接口本身与平台无关，但本项目的采集调度与通知链路没有做跨平台适配。
- 机器关机/睡眠期间不采集；唤醒后计划任务自动补跑，趋势曲线如实断档。
- Codex `access_token` 到期后，开一次 Codex 桌面端即可自动续期。
- GLM 的「充值记录」是支付凭证，不代表未消费额度——看板已标注，余额以余额卡为准。
- 通知依赖 Windows 通知中心未被「专注助手」完全屏蔽；收不到时检查 系统设置→通知。
- **额度去向归因只覆盖 Codex**：DeepSeek/GLM 是按量计费的余额制，没有"会话"概念；两家用「余额消耗」口径（热力图/框选统计已有）。
- **跨通道「统一 token 用量」做不到**：ThinCoder 本地不持久化 token 用量（会话与日志里的 `prompt_tokens` 都是工具输出引用的源码片段，`~/.thincoder/` 下也没有统计文件）。因此 Codex 只有 tokens、DeepSeek/GLM 只有金额、ThinCoder 只有回合与消息数——**不硬凑统一数字**。
- 归因数字是**本地会话文件里的 token 计数**，与官方账单可能有出入（重试、缓存命中等不计入），用于比较项目间的相对占比是可靠的。
- 托盘常驻会占用一个 PowerShell 进程（约 80MB 内存、CPU 接近 0）；不想要就设 `tray.enabled=false` 并重跑安装。
- **本项目不使用 `fs.cpSync`**：Node v24.14.0 在中文路径下调用它会原生崩溃（exit `0xC0000409`，无 JS 异常可捕获），批量拷贝一律走逐文件 `copyFileSync`（`程序/tools/backup.mjs` 内有说明）。
- **所有 `.vbs` / `.bat` 必须保持纯 ASCII**（当前 6 个 `.vbs` + 4 个 `.bat`，已逐字节核对）：Windows 脚本宿主按系统 ANSI 代码页读取 `.vbs`（中文 Windows 为 GBK 一类），UTF-8 中文注释可能吞掉行尾换行并破坏解析（已发生过一次，报 `'loop' 没有 'do'`）。文件头已写明原因；`快捷操作\启用自动采集.vbs` 的中文提示经 `程序/tools/setup-notify.mjs`（正常路径）与内嵌 base64 载荷（退化路径）承载。
- **`运行协议.vbs` 里"剥离尾随斜杠"那段不能删**：ShellExecute 会把 `aiquotaboard://action?params` 规范化成 `aiquotaboard://action/?params`（在 `?` 前插入斜杠），不剥离就匹配不到任何动作、静默失败——曾导致看板与通知上的**所有**按钮失效。
- **通知应用名的校验不能用 `reg query` 的输出比对中文**：它按控制台代码页输出，非 UTF-8 代码页下会乱码，造成"明明写对了却报失败"的环境相关假故障；现改为 PowerShell 读注册表 + 码点比对（`程序/tools/register-app-id.mjs` 内有说明）。
